# Свипы генерации

Разовые харнессы, которыми мерили ручки генерации, и **сырые результаты этих
замеров**. Лежат здесь потому, что выводы в [`docs/OPEN.md`](../../docs/OPEN.md)
и [`docs/CLOSED.md`](../../docs/CLOSED.md) ссылаются на них поимённо — без
файлов ссылка ведёт в пустоту, а перепроверить число нечем.

Это не часть бота и не запускается в CI: скрипты ходят в копию прод-базы
(`db_prod_copy/markov.db`), которой в репозитории нет и не будет.

| Файл | Что это |
|---|---|
| `sweep_2026-07-20.py` | Проход A: 39 конфигураций × 3 сида × 200 генераций. Итог — карта сильных и инертных ручек. |
| `sweep_2026-07-20b.py` | Проход B: 15 плеч × 10 сидов × 400 = 4000 генераций на плечо, парные разности по сидам с CI. Опроверг три вердикта прохода A — тот был статистически недомощен. |
| `analyze_2026-07-20.py` | Сводная таблица по `sweep_2026-07-20_results.jsonl`. |
| `selfecho_2026-07-21.py` | Целевой замер самоэха (`бот A → человек → бот B`). Обычный `eval_prod` этой петли не моделирует, поэтому фикс был ему не виден. |
| `*_results.jsonl` | Сырые метрики по каждому плечу — то, на что ссылаются документы. |
| `sweep_2026-07-20_summary.txt` | Человекочитаемая сводка прохода A. |

## Как запускать

```bash
python tools/sweeps/sweep_2026-07-20b.py       # нужна db_prod_copy/markov.db
python tools/sweeps/analyze_2026-07-20.py      # только читает готовый .jsonl
```

## Урок методики (2026-07-21)

Проход A на 200 генерациях выдал три ложных вердикта «шумная/немонотонная»:
межсидовый разброс `context_anchored` там ~0.040, шире большинства реальных
эффектов ручек (±0.02–0.04). На 400 генерациях разброс ~0.015. Отсюда правило,
запечённое в `DEFAULT_GENERATIONS` в `tools/eval_prod.py`: **≥400 генераций на
плечо**, и сравнивать парные разности по сидам, а не абсолютные уровни.

Проверка побайтовой неизменности поведения после рефакторинга — отдельный
инструмент, [`tools/generation_hash.py`](../generation_hash.py).
