## Requirements
### Requirement: Ключ шифрования выводится функцией вывода ключа с доменной меткой

Ключ, которым шифруются персональные данные подписчиков, SHALL выводиться из секрета конфигурации функцией вывода ключа с доменной меткой, а не одиночным хешированием.

Разные назначения SHALL получать разные ключи из разных меток, чтобы компрометация одного назначения не давала ключа к другому.

#### Scenario: Секрет используется в двух назначениях

- **WHEN** один и тот же секрет служит источником для шифрования подписок и для другого назначения
- **THEN** выведенные ключи различаются

### Requirement: Секреты обязаны иметь достаточную длину

Система SHALL отказываться стартовать, если секрет, из которого выводятся ключи, короче установленного порога.

Отказ SHALL называть настройку и требуемую длину. Система MUST NOT стартовать со слабым секретом, подставив значение по умолчанию или ограничившись предупреждением: слабый ключ, о котором никто не узнал, — это и есть отсутствующая защита.

#### Scenario: Слишком короткий секрет

- **WHEN** секрет короче порога
- **THEN** запуск завершается ошибкой с именем настройки и требуемой длиной

#### Scenario: Плейсхолдер из примера конфигурации

- **WHEN** секрет совпадает с плейсхолдером из файла-примера
- **THEN** запуск завершается ошибкой

### Requirement: Смена схемы ключа не теряет уже сохранённые данные

При смене схемы вывода ключа система SHALL продолжать читать данные, зашифрованные прежней схемой.

Новые записи SHALL шифроваться актуальным ключом, а уже сохранённые SHALL переходить на него при очередной перезаписи — без отдельной остановки сервиса и без единовременной миграции всей таблицы.

#### Scenario: Чтение старой записи

- **WHEN** система читает подписку, зашифрованную прежней схемой
- **THEN** данные расшифровываются успешно

#### Scenario: Перезапись старой записи

- **WHEN** профиль подписчика обновляется после смены схемы
- **THEN** запись сохраняется зашифрованной актуальным ключом

### Requirement: Анонимные идентификаторы сравниваются по хранимому значению

Чтобы исключить вызывающего из списка упоминаний, система SHALL сравнивать его анонимный идентификатор с хранимым анонимным идентификатором подписчика.

Система MUST NOT расшифровывать персональные данные подписчика ради этого сравнения: расшифровка нужна для сборки упоминания, а не для проверки совпадения.

Сравнение SHALL выполняться способом, не зависящим от позиции первого несовпадения.

#### Scenario: Вызывающий подписан на собственный чат

- **WHEN** подписчик, вызвавший команду, присутствует в списке
- **THEN** он исключается из упоминаний
- **AND** его персональные данные для этого не расшифровываются
