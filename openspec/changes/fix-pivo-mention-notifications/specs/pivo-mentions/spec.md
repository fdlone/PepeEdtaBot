## Purpose

Описывает, как `/pivo` зовёт подписчиков: упоминание должно не просто отрисоваться в сообщении, а сделать человека упомянутым для Telegram, чтобы он получил уведомление. Здесь же — резервные пути, когда предпочтительный способ упоминания недоступен, и способ проверить, каким путём построено упоминание конкретного подписчика.

## ADDED Requirements

### Requirement: Упоминание подписчика строится по идентификатору пользователя

Система SHALL строить упоминание подписчика `/pivo` как упоминание по идентификатору пользователя (inline-ссылка `tg://user?id=<user_id>`, которую Telegram превращает в entity типа `text_mention`), независимо от того, есть ли у подписчика `@ник`.

Система MUST NOT полагаться на сопоставление строки `@ник` как на основной способ упоминания: корректно отрисованный и кликабельный `@ник` не является подтверждением того, что получатель помечен упомянутым.

#### Scenario: У подписчика есть @ник

- **WHEN** `/pivo` собирает упоминание подписчика, у которого сохранён `@ник`, и упоминание по идентификатору доступно
- **THEN** в сообщение попадает упоминание по идентификатору этого подписчика
- **AND** видимый текст упоминания остаётся `@ник` — читаемость сообщения в чате не меняется

#### Scenario: У подписчика нет @ника

- **WHEN** `/pivo` собирает упоминание подписчика без `@ника`
- **THEN** в сообщение попадает упоминание по идентификатору с отображаемым именем подписчика
- **AND** поведение совпадает с прежним — для этой группы подписчиков ничего не меняется

### Requirement: Резервный путь, когда упоминание по идентификатору недоступно

Система SHALL возвращаться к упоминанию строкой `@ник`, когда упоминание по идентификатору для конкретного подписчика заведомо не сработает — в частности, когда настройки приватности пользователя запрещают ссылки `tg://user?id=` вне личного чата с ним.

Когда недоступны оба пути, система SHALL исключить подписчика из списка упоминаний, не ломая сообщение и не подставляя вместо упоминания сырой идентификатор.

#### Scenario: Приватность запрещает ссылку по идентификатору

- **WHEN** у подписчика включена приватность, ограничивающая ссылки `tg://user?id=`, и у него есть `@ник`
- **THEN** в сообщение попадает упоминание строкой `@ник`

#### Scenario: Ни идентификатор, ни ник не пригодны

- **WHEN** упоминание по идентификатору недоступно и `@ника` у подписчика нет
- **THEN** подписчик пропускается
- **AND** остальные подписчики упоминаются как обычно, сообщение отправляется

### Requirement: Способ упоминания переключается без деплоя

Система SHALL предоставлять настройку, переводящую построение упоминаний обратно на строковый путь `@ник` для всех подписчиков.

Настройка SHALL применяться к следующему вызову `/pivo` без перезапуска процесса и SHALL иметь значение по умолчанию, соответствующее упоминанию по идентификатору.

#### Scenario: Откат к строковым упоминаниям

- **WHEN** настройка выключена и вызывается `/pivo`
- **THEN** упоминания подписчиков с `@ником` строятся строкой `@ник`, как до изменения

#### Scenario: Значение по умолчанию

- **WHEN** настройка не задавалась ни в окружении, ни в рантайме
- **THEN** используется упоминание по идентификатору

### Requirement: Диагностика построения упоминаний

Система SHALL предоставлять владельцу бота команду, которая для текущего чата показывает по каждому подписчику `/pivo`, каким путём построено его упоминание (по идентификатору, строкой `@ник` или пропущен) и по какой причине выбран этот путь.

Команда SHALL быть доступна только владельцу бота и SHALL NOT раскрывать о подписчиках больше, чем уже видно в самом сообщении `/pivo`. Команда MUST NOT писать расшифрованные ники и идентификаторы подписчиков в лог.

#### Scenario: Владелец запрашивает диагностику

- **WHEN** владелец бота вызывает команду диагностики в групповом чате
- **THEN** он получает ответ со списком подписчиков этого чата и выбранным для каждого путём упоминания с причиной

#### Scenario: Команду вызывает не владелец

- **WHEN** команду диагностики вызывает любой другой участник, включая администратора чата
- **THEN** система отказывает в выполнении и не раскрывает состав подписчиков

### Requirement: Наблюдаемость результата без раскрытия данных

Система SHALL логировать по каждому вызову `/pivo` распределение подписчиков по путям упоминания в агрегированном виде (сколько по идентификатору, сколько строкой, сколько пропущено).

Логи MUST NOT содержать расшифрованных ников, отображаемых имён и идентификаторов подписчиков; `chat_id` в этих записях SHALL быть маскирован принятым в проекте способом.

#### Scenario: Запись о вызове

- **WHEN** `/pivo` успешно отправил сообщение
- **THEN** в лог попадает агрегат по путям упоминания и маскированный `chat_id`
- **AND** в записи нет ни одного персонального идентификатора подписчика
