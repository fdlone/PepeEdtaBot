# Meme regression: support floor and a share-based gate (M3R-130)

## Why

Гейт `meme_regression_pass` требует, чтобы **каждая** n-грамма фиксированного
набора воспроизвелась хотя бы раз, а сам набор строится запросом
`SELECT w1, w2, w3 FROM chat_hot_ngrams ... ORDER BY cnt DESC`
(`tools/eval/prompts.py`) — **без какого-либо порога поддержки**. Карта §3.6
записала следствие: 16 из 27 мемов набора имеют поддержку в одно сообщение, и
состав невоспроизведённых плавает между прогонами, то есть гейт меряет удачу.

Замер на свежей прод-копии (01.09) показывает, что дефект глубже записанного:
в `chat_hot_ngrams` главного чата **1079 строк из 1097 имеют `cnt = 1`**, ещё
16 — `cnt = 2`, две — `cnt = 3`. Окно горячих n-грамм затухает (период
полураспада 7 дней), поэтому единичная поддержка — не аномалия набора, а
нормальное состояние таблицы. Требовать воспроизведения n-граммы, встреченной
однажды, значит требовать совпадения.

Второе: гейт считается **только для C0** и помечен в отчёте «informational at
Phase 0» (`tools/eval/report.py`). То есть он проверяет, воспроизводит ли
базлайн собственный набор, и по построению не может поймать конфигурацию,
которая стирает память чата, — ради чего заведён.

## What Changes

- **Порог поддержки при генерации набора**: в набор попадают только n-граммы с
  `cnt ≥ 2`. Порог записывается в файл порогов вместе с обоснованием и
  применяется при построении `eval_prompts.yaml`.
- **Метрика вместо бинарности**: публикуется **доля воспроизведённых** мемов с
  абсолютными числами (правило проекта «никакой доли без знаменателя»), и
  считается она **для каждого арма**, а не только для C0.
- **Гейт становится относительным к C0**: конфигурация проваливает проверку,
  когда её доля ниже доли C0 более чем на пре-регистрированный допуск.
  Абсолютная планка отвергнута сознательно — прецедент фазы 4, где планка 70%
  не была взята ни одним из двух армов и измерила строгость оценщиков, а не
  алгоритм; здесь абсолютная планка мерила бы толщину корпуса.
- **Минимальный размер набора**: если после порога поддержки в наборе меньше
  пре-регистрированного минимума, гейт отдаёт `insufficient data` и печатает
  размер набора — доля по трём мемам не вердикт, а шум.
- **Перегенерация набора меняет `version` промптов** — осознанный разрыв
  сопоставимости с прошлыми отчётами, обозначается в самом отчёте.

Не входит в объём: сам прогон вердикта, изменение генерации, ручки конвейера.
Изменение целиком в `tools/eval`.

## Capabilities

### New Capabilities

_нет_

### Modified Capabilities

- `generation-eval`: требование о нормативных определениях метрик дополняется
  правилами набора мем-регресса — порогом поддержки, долей вместо бинарности,
  минимальным размером набора и относительной формой гейта.

## Impact

- `tools/eval/prompts.py` (порог при построении набора),
  `tools/eval/metrics.py` (доля вместо «все воспроизведены»),
  `tools/eval/report.py` (по-армовый расчёт и строка вердикта),
  `tools/eval/eval_thresholds.yaml` (новый блок с порогом, допуском и
  минимальным размером набора).
- `docs/v2/05_MARKOV_2_0R_EVAL_PROTOCOL.md` §3.5 — врезка «известный дефект»
  заменяется описанием починенного гейта.
- `docs/GENERATION_MAP.md` §3.6 — аннотируется закрытием.
- `generation_hash`: не задет по построению — путь генерации не трогается.
