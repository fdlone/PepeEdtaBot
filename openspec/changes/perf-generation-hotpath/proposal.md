## Why

Конвейер генерации делает на каждый ответ до десяти попыток, и в каждой повторяет работу, результат которой не меняется между попытками:

- функции взвешенного выбора сортируют входной список **на каждом вызове**. Для стартов это 4 482 строки на живом чате (копия прода) при десяти попытках на ответ, плюс вызовы из механизма смены темы. Списки при этом уже лежат в кэше генератора и меняются только при обучении — сортировать их достаточно один раз при заполнении кэша;
- подбор замены для слот-мутации линейно обходит **весь** частотный словарь чата на каждый слот и для выживших кандидатов дёргает морфологический разбор. Отбор по двухбуквенному окончанию выполняется внутри цикла, хотя именно он отсекает подавляющее большинство слов — индекс «окончание → слова» превращает обход словаря в обход небольшой корзины;
- выборка «горячих» n-грамм во второй ветке агрегирует всю таблицу переходов чата (`GROUP BY`) при каждом вызове;
- проверка «ответ пересказывает контекст» использует поиск наибольшей общей подпоследовательности с кубической в худшем случае сложностью и вызывается дважды на каждую завершённую попытку.

Ни один из пунктов не меняет того, что видит пользователь, — это чистая экономия на горячем пути ответа.

## What Changes

- Кэшированные списки стартов и переходов хранятся уже отсортированными; функции взвешенного выбора перестают сортировать вход и полагаются на порядок, зафиксированный при заполнении кэша.
- Частотный словарь чата при загрузке индексируется по окончанию слова; подбор замены обходит только подходящую корзину.
- Агрегат для «горячих» n-грамм считается по n-граммам, реально присутствующим в окне, а не по всей таблице переходов чата.
- Поиск общей подпоследовательности заменяется на линейно-квадратичный алгоритм с тем же результатом.
- **Инвариант**: при одинаковом состоянии генератора и одинаковом источнике случайности выход должен остаться прежним. Это проверяется существующими характеризационными тестами генерации и хешем базовой линии (`tools/generation_hash.py`).

## Impact

- **Код**: `app/core/markov.py` (порядок в кэшах и функции выбора), `app/core/slot_mutation.py` (индекс по окончанию), `app/services/learning_service.py` (построение индекса при загрузке частот), `app/repositories/chat_hot_ngrams_repo.py` (агрегат).
- **Риск**: смена порядка элементов меняет последовательность обращений к генератору случайных чисел и способна сдвинуть выход при фиксированном зерне. Поэтому порядок должен остаться **тем же самым** (та же сортировка, просто выполненная раньше), а не «каким-нибудь».
- **Проверка**: характеризационные тесты генерации, `tools/generation_hash.py` до и после, замер задержки генерации на копии прода.
- **Тесты**: существующие; новые — на индекс по окончанию (замена находится там же, где и раньше) и на агрегат горячих n-грамм.
