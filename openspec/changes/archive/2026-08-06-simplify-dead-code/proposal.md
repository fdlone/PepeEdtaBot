## Why

В коде накопились фрагменты, которые ничего не делают, но требуют внимания при каждом чтении и правке:

- константа минимальной длины обучаемого сообщения объявлена и не используется нигде — проверка длины смотрит только на верхнюю границу. Читатель разумно предполагает, что нижняя граница работает;
- шесть публичных функций и методов не вызываются из рабочего кода: проверка существования сообщения в базе (вместе с методом репозитория), обёртка генерации без трассировки, обёртка отправки ответа с явными таймингами, сборка сообщения `/pivo` без анти-повтора, построение окон 4-грамм по тексту (используется только инструментом оценки);
- поле «похожести» у результата сопоставления контекстных состояний всегда равно единице и участвует только в сортировке самого себя;
- строка запасного обращения `«Господа дегенераты»` объявлена в двух модулях, и один из них сравнивает значение со **своей** копией — расхождение констант тихо сломает подавление строки с упоминаниями;
- два типа с одинаковыми восемью полями (трассировка генерации и результат попытки) конструируются позиционно на пяти местах, из-за чего порядок аргументов приходится удерживать в голове;
- оценка кандидата считает релевантность контекста, которую единственный рабочий путь тут же перезаписывает версией с учётом IDF — вычисление выбрасывается для каждого кандидата;
- кандидат нормализуется двумя разными способами в одном вызове (для сравнения с текущим сообщением и для анти-повтора), и разница между ними ничем не объяснена.

## What Changes

- Неиспользуемая константа удаляется либо превращается в работающую проверку — по факту: нижняя граница длины уже обеспечена требованием к числу токенов, поэтому константа удаляется, а инвариант фиксируется комментарием.
- Функции, вызываемые только из тестов и инструментов, удаляются; там, где вызывающий — инструмент оценки, функция переезжает к нему.
- Поле «похожести» удаляется вместе с участием в сортировке.
- Строка запасного обращения остаётся в одном месте — доменном модуле; второй модуль импортирует её.
- Два типа с одинаковыми полями объединяются, конструирование переводится на именованные аргументы.
- Оценка кандидата перестаёт считать поле, которое всегда перезаписывается.
- Нормализация кандидата сводится к одной функции с явными вариантами.

## Что не удалено и почему

Два пункта при реализации не подтвердились как «мёртвый код»; они оставлены с
явным объяснением в коде, чтобы следующий читатель не пометил их снова.

- **`MarkovGenerator.generate_text`** — сокращённая форма публичного API (текст
  без трассировки). Её вызывают около пятнадцати тестов; удаление означало бы
  разбор кортежа на каждом вызове ради тридцати строк переадресации. Это не
  мёртвый код, а вторая форма вызова; помечена как таковая.
- **Слияние `GenerationTrace` и `_GenerationAttempt`** не делается: типы похожи
  по полям, но не по смыслу — первый суммирует все попытки и его форму читают
  инструменты оценки, второй описывает одну попытку и несёт текст. Настоящий
  дефект был в позиционном конструировании на пяти местах; он и устранён —
  сборка идёт по именам.

Обёртки, которые действительно вызывались только из тестов и инструментов
(`build_pivo_message`, построение окон 4-грамм по тексту), не удалены, а
перенесены к своим вызывающим: из продового кода они ушли, краткость вызова у
тестов осталась.

## Impact

- **Код**: `app/handlers/learning.py`, `app/infrastructure/database.py`, `app/repositories/messages_repo.py`, `app/core/markov.py`, `app/core/context_state_matcher.py`, `app/core/candidate_scorer.py`, `app/core/response_generator.py`, `app/domain/pivo.py`, `app/services/pivo_message_builder.py`, `app/services/learning_service.py`, `tools/eval_prod.py`.
- **Тесты**: часть тестов проверяет именно удаляемые обёртки — они переписываются на рабочий путь либо удаляются вместе с кодом. Покрытие не должно упасть ниже действующего порога.
- **Риск**: удаление того, что кто-то считал точкой расширения. Каждое удаление сопровождается проверкой на отсутствие вызовов из `app/`, `main.py` и `tools/`.
- **Наблюдаемое поведение**: не меняется. Единственная тонкость — объединение типов и убранное вычисление не должны сдвинуть последовательность обращений к генератору случайных чисел; проверяется хешем базовой линии генерации.
