## Context

Гейты маршрутов уже существуют по одному на маршрут (`l1_hot_channel` для
hot, планки `assoc_pilot` для пилота). Роадмап M3R-220 требует общий гейт
промоушена с условием Escape в форме «доля входов ниже 2» — форма
`single_trajectory_samples` уже реализована для `selection_window`
(M3R-100) и переиспользуется здесь без изменений.

## Decisions

### D1. Один блок на все маршруты, маршрут выводится из данных

`route_gate` не знает имени маршрута: он берёт множество маршрутов в пулах
арма минус множество маршрутов в пулах C0. Ровно один новый маршрут —
предмет гейта; ноль или два — `insufficient data` с текстом. Это избавляет
гейт от карты «ручка → маршрут» и делает его пригодным для фразового
маршрута M3R-210 без правок.

### D2. Условия и их роли — записаны до прогона

| условие | роль | планка |
|---|---|---|
| present-доля маршрута | coverage | ≥ 0.10, иначе `insufficient data` |
| доля входов с одной траекторией в окне, парная Δ | **must-improve** | значимо и ≤ −0.05 (5 п.п.), иначе fail |
| affinity без копий, Δ | must-not-worsen | значимое падение = fail (оба режима) |
| copy, repetition, Δ | must-not-worsen | значимый рост = fail |
| ECB пула | инвариант | абсолютный ≥ 4.0 (та же планка, что у `structural_escape`) |
| p95 | бюджет | ≤ 150 мс |
| связность, соло-раунд M3R-020 | условие качества | не ниже C0 − 10 п.п.; без раунда — `insufficient data`, никогда не pass |
| два режима | `requires_both_modes` | одномодовый прогон — `insufficient data` |

Почему must-improve именно так: пилот показал, что среднее escape окна маршрут
не двигает, а окно у 36% ctx-входов — одна траектория (M3R-011). Маршрут,
который «создаёт пространство», обязан уменьшать эту долю; среднее, которое
C0 и так берёт, гейтом быть не может (оговорка вердикта M3R-011).

Связность читается в `ctx` — режиме 89% прода (O7); в `noctx` условие не
требуется, чтобы не удваивать ручной труд владельца, и это записано в блоке.
Ожидание до прогона: доля одиночных входов в ctx (36% у C0) при двух слотах
падает на 3–6 п.п. — ассоциат выигрывает 19% пулов, где присутствует, но
входит ли он в окно, не выигрывая, пилот не мерил; в noctx (6% у C0) двигать
почти нечего, и там условие может не набрать значимости.

### D3. Грид — те же армы, что у пилота, под новым префиксом

`C11a20` / `C11a40` повторяют `assoc_slot_ratio` 0.2 / 0.4: пилот и гейт
отвечают на разные вопросы, и переиспользовать его отчёты под гейт нельзя
(гейт пре-регистрирован после пилота). Префикс `C11` → `route_gate`.

### D4. Соло-раунд

`python -m tools.solo_rating_round prepare --label assoc-gate --matrix
tools/eval/matrix_route_gate.yaml --context-mode ctx` — список в
`rating_rounds/assoc-gate/` (вне репозитория). Оценка владельца, затем
`score` и прогон ctx с `--solo-rating`. Без раунда вердикт ctx —
`insufficient data` по построению.
