## Context

Канал L2 проходит пять гейтов подряд (`_apply_user_quirk`,
`app/services/reply_pipeline.py`): адресность → ручка → суточный лимит на
пару (чат, человек) → ролл `random() < user_quirk_chance` → порог
`interactions ≥ user_quirk_min_interactions`. Воронка 24.08→01.09:

| гейт | дошло | отказало |
|---|---|---|
| адресность | 63 | 12 |
| ручка | 51 | 0 |
| сутки | 51 | 7 |
| ролл (0.1) | 44 | 41 |
| порог (25) | 3 | 1 |

`/quirk_stats` 21.08: людей со счётчиком 6, максимум 57, порог 25 перешагнул
один. Счётчик затухает за ~30 дней.

## Decisions

### D1. Шанс 0.3, порог 10 — одно изменение, не два

Ролл — главный отказ, порог — второй по дороге к нему. Менять их порознь
значило бы два окна наблюдения ради двух чисел, которые читаются из одной
воронки одновременно: гейт ролла и гейт порога считаются раздельно, поэтому
вклад каждого виден и при совместной правке.

- **0.3**, а не 0.5: при 0.5 ролл перестаёт быть гейтом (половина адресованных
  ответов к завсегдатаю получает причуду), и единственным ограничителем
  остаётся суточный лимит — канал из «иногда» превращается в «каждый день
  каждому». 0.3 утраивает частоту, оставляя ролл главным гейтом.
- **10**, а не 5: при затухании ~30 дней десять отвеченных обращений в месяц —
  это человек, с которым бот действительно регулярно разговаривает; пять
  берутся за один живой вечер, и «завсегдатаем» стал бы любой заглянувший.
  Распределение по диапазонам `/quirk_stats` (введено `observe-user-quirk-
  channel`) на момент решения не снималось — порог выбран по смыслу счётчика,
  проверяется окном ниже.

### D2. Ожидание записано до окна

При прежнем темпе (63 адресованных за ~8 дней) воронка при 0.3 / 10 должна
дать порядка **13 прошедших ролл** (44 × 0.3) и **8–10 сработавших** причуд
за такое же окно против 2. Читать по гейтам после сути активности без
рестартов:

| наблюдение | вывод |
|---|---|
| сработавших ≥ 6 за окно, порог режет ≤ трети дошедших | рабочая точка найдена, закрыть с цифрами |
| ролл по-прежнему режет > 80% при 0.3 | ролл считается иначе, чем читается из кода — разбор, не подкрутка |
| порог режет > половины дошедших | завсегдатаев в чате меньше, чем счётчиков; снять распределение `/quirk_stats` и решать по нему |
| владелец видит причуды как навязчивые | откат `/set user_quirk_chance 0.1` без рестарта, порог оставить |

### D3. Хеш генерации не задет по построению

Канал работает после `generate_with_result`, розыгрыш берёт из общего `random`
модуля, а не из `rng` генерации; `tools/generation_hash.py` канал не
исполняет. Ожидание «сдвига нет ни на одном снимке» записывается в
`hash-log.md` до правок и сверяется после.

## Risks

- Суточный лимит на пару обнуляется рестартом (известно, не трогаем): после
  редеплоя первый день даст чуть больше причуд, чем стационарный режим.
- Порог 10 достижим быстрее, чем 25, для людей, которые *отвечают боту* —
  reply на сообщение бота считается обращением. Это ровно те люди, для кого
  канал задуман.
