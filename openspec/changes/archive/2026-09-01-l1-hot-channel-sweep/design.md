## Context

L1-затравка живёт в `ReplyPipeline._hot_ngram_seed`: не для адресованных
ответов, ролл `random() < hot_ngram_seed_chance` (0.25), затем `get_hot`
(top-8 по счётчику с тай-брейком) и `random.choice`. Затравка попадает в
`_pick_seed_start` генератора: старт находится, только если n-грамма есть в
`starts3`/`starts` (то есть открывала сообщение) — иначе затравка молча
ничего не даёт. `tools/eval` подаёт `seed=None` всегда.

## Decisions

### D1. Затравка моделируется только в noctx

Конвейер сидирует лишь самостоятельные ответы; в проде при
`reply_context_only_for_replies = true` контекст получают ровно адресованные.
Значит «ответ с затравкой» и «ответ без контекста» — один и тот же класс, и
режим `noctx` его моделирует. В ctx канал инертен по построению, и ctx-прогон
грида измеряет только вторую половину эффекта — `protected_tokens` у мутаций
(они читают те же пороги в обоих режимах).

### D2. Отдельный ГСЧ, RNG генерации не трогается

Розыгрыш и выбор — `random.Random(seed * 100_000 + index + 50_000_000)`:
детерминирован по (сид, индекс генерации), не пересекается с ГСЧ генерации
(`seed * 100_000 + index`) и не сдвигает C0 ни на бит — при пустом пуле
затравки нет, а порядок потребления `rng` прежний. Пул `get_hot` читается
один раз на (арм, сид) — так делает и `_ProdVerbatimChecker`.

### D3. Coverage — по старту, а не по розыгрышу

Розыгрыш может выбрать n-грамму, которая не открывает ни одного сообщения; в
записи хранятся оба факта (`seed_drawn`, `start_source`), гейт читает второй.
Перепись показала, что из top-8 открывают старт 3–5, то есть верхняя оценка
coverage при шансе 0.25 — 9–16% ответов noctx.

### D4. Must-improve — `historical_meme_rate` в noctx, с оговоркой о цикличности

Набор мем-регресса (M3R-130) строится из тех же `chat_hot_ngrams` с полом
поддержки 2, что и пул затравки. Метрика поэтому измеряет не «бот нашёл
мемы», а **доживает ли выбранная затравка до ответа** через финализацию,
verbatim-штраф и отбор — это и есть вопрос канала (R4: «девятка мемов не
появляется ни в одном кандидате»). Оговорка печатается в вердикте.

### D5. Связность — в noctx, соло-протоколом

Только там канал производит текст; в ctx он меняет лишь защиту токенов у
мутаций. Раунд готовится `python -m tools.solo_rating_round prepare
--matrix tools/eval/matrix_l1_grid.yaml --context-mode noctx`; без него гейт
noctx — `insufficient data`, никогда `pass`. Пороги валидности раунда — из
блока `phase9_interp` (инструмент их не дублирует по своему design).

### D6. Что изменение НЕ делает

Не меняет дефолты `hot_ngram_*`. Промоушен — решение владельца по вердикту и
раунду связности, отдельным изменением: гейт роадмапа включает связность, и
автоматической половины для включения недостаточно.

## Risks

- Три-пять открывающих старт n-грамм — узкий пул; `random.choice` из 8 будет
  повторять одни и те же зачины. Анти-повтор в eval не моделируется, так что
  `repetition_rate` арма — нижняя оценка живого.
- `historical_meme_rate` считается на четверти промптов (`meme-bait`);
  при 1500 генерациях на арм это 375 — разрешение ~5 п.п.
