## Why

Документация должна описывать действительное, а не желаемое. По итогам аудита в ней уже есть расхождения, а предыдущие изменения этого пакета добавят новые:

- в шапке README сказано «privacy-first storage … no raw texts kept» и «сырые тексты не хранятся», тогда как `messages.normalized_text` хранит текст сообщения целиком (без ссылок, `@упоминаний` и распознанных персональных данных, со схлопнутыми пробелами) в пределах окна ретенции. Ниже, в разделе Privacy, то же самое описано корректно — документ противоречит сам себе;
- после изменений пакета меняются: поведение при исчерпанной квоте `/pivo`, смысл предела на число упоминаний, схема вывода ключа шифрования и требования к длине секретов, права на полную форму показа настроек, состав и пределы кэшей, направление зависимостей между слоями, состав слоя сервисов.

Отдельно фиксируется известное ограничение, которое сознательно не закрывается: статическая проверка типов в CI охватывает только `app/`. Расширение на `tests/` и `tools/` даёт 261 ошибку — это самостоятельная задача, а не побочный эффект аудита, и попытка сделать её «заодно» размыла бы ревью всех остальных изменений.

## What Changes

- README, `docs/ARCHITECTURE.md`, `docs/OPERATIONS.md`, `.env.example` приводятся в соответствие фактическому состоянию кода на момент завершения аудита.
- Формулировка про «сырые тексты» заменяется на точную: что именно удаляется при нормализации, что хранится и как долго.
- Описания настроек: `PIVO_SUBSCRIBER_FANOUT_LIMIT` (порог усечения, а не отказа), требования к длине секретов, новые пределы кэшей, если они появятся как настройки.
- Удаляются упоминания того, чего в коде больше нет после изменений пакета; добавляется то, что появилось.
- Каждый факт в документации сверяется с кодом: настройки — с реестром, команды — с обработчиками, таблицы — с миграциями, гарантии приватности — с местами записи.
- Известное ограничение по охвату проверки типов фиксируется в README или `docs/OPERATIONS.md` как принятое решение, а не как недосмотр.

## Impact

- **Файлы**: `README.md`, `docs/ARCHITECTURE.md`, `docs/OPERATIONS.md`, `.env.example`.
- **Порядок**: изменение выполняется **последним**, после закрытия всех остальных изменений пакета — иначе документация опишет промежуточное состояние.
- **Резюме аудита** (что изменено, какие риски закрыты) помещается в архивное предложение этого изменения, а не в README.
- **Тесты**: проверяется соответствие списка настроек в `.env.example` реестру runtime-ключей — если такого теста ещё нет, он добавляется здесь.

## Резюме аудита

Аудит по осям «упрощение / безопасность / производительность / код-ревью»,
2026-08-06 — 2026-08-07, ветка `audit/pivo-security-and-privacy`. Тринадцать
изменений, каждое отдельным коммитом.

**Безопасность и приватность.** Отказ `/pivo` по исчерпанной квоте перестал
быть потоком сообщений от бота; предел на подписчиков стал усечением с
пометкой, а не отказом, ломавшим команду для всего чата навсегда. Ключ
шифрования `/pivo` выводится через HKDF с доменной меткой вместо голого
SHA-256, чтение идёт набором ключей — миграции данных не потребовалось; порог
длины секретов поднят до 32 символов (ломающее для эксплуатации, но текущие
секреты длиннее). Полная форма `/config` закрыта тем же кругом, который может
эти значения менять. Реальные `chat_id` убраны из отслеживаемых файлов, включая
артефакты самого аудита, и закрыты тестом-сторожем.

**Производительность** (замеры на копии прода, до → после): генерация ответа
91.0 → 63.5 мс; чтение объёма модели, происходящее на каждое сообщение,
12.7 → 0.014 мс; выборка «горячих» n-грамм 40.8 → 0.42 мс; кэши обучения после
выученного сообщения ~95 → 0.015 мс. Ни одно из ускорений не изменило
поведения: хеш генерации на прод-копии (1000 генераций) остался прежним на
каждом шаге аудита.

**Упрощение.** Ядро генерации перестало зависеть от инфраструктуры — появился
порт чтения цепи. Из фасада БД убраны сорок методов-делегатов: потребители
ходят в репозитории напрямую. Конвейер ответа (430 строк в одной функции
обработчика) вынесен в сервис и разложен на три шага; ветки политики ответа
теперь проверяются без моков Telegram.

**Что осталось открытым.** Сбой суточного затухания статистики роняет
сохранение сообщения целиком (`decay_flavor_stats_if_due` вызывается из
`save_message_and_update_model`) — требуется решение, должен ли сбой
обслуживания стоить сообщения. Охват `mypy` намеренно оставлен на `app/`.

Тестов 878 → 941, покрытие 94% при пороге 87%.
