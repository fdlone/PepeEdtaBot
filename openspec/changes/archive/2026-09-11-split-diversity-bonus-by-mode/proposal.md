## Why

O19 (M3R-100, шаг 2): бонус различности `selection_diversity_bonus` 0.2
открывает окно отбора, но в ctx платит тематичностью — affinity без копий
−0.011\* (−4%), гейт `selection_window` без допуска провален; в noctx тот же
бонус **берёт все условия гейта** (coverage −6.1 п.п.\*, escape +0.413\*,
copy и repetition в шуме — `eval_2026-09-02_selection-grid-verdict.md`), потому
что тематичности там нет по построению. Одна ручка на оба режима заставляет
выбирать между «платить в ctx» и «терять в noctx». **Решение владельца
2026-09-11 (O19, вариант 2):** расщепить бонус по режиму — 0.2 только для
ответов без контекста (11% прода), ctx не трогать. Прямой аналог оговорки
фазы 9: провал в одном режиме при проходе в другом допускает разные
значения решением владельца.

## What Changes

- Новая ручка `selection_diversity_bonus_noctx` (env
  `SELECTION_DIVERSITY_BONUS_NOCTX`, 0..1, **дефолт 0.2**): бонус различности
  для ответов **без контекста**. Существующая `selection_diversity_bonus`
  (дефолт 0) остаётся бонусом для ответов **с контекстом**; её семантика и
  дефолт не меняются.
- Выбор ручки — по наличию `context_tokens` у запроса, в единственной точке
  применения бонуса; механика `apply_diversity_bonus` не меняется.
- `generation_hash` не сдвигается: гард генерирует только с контекстом
  (`tools/generation_hash.py`), а ctx-ручка остаётся 0. Ответы без контекста
  в проде **меняются** — это и есть цель; их прод-доля 11%.
- Базлайн C0 харнесса в `noctx` с этого момента несёт бонус 0.2 (C0 =
  дефолты реестра): noctx-отчёты до и после несопоставимы по абсолютным
  значениям — осознанный разрыв, записывается в вердикт-заметку и CLOSED.
