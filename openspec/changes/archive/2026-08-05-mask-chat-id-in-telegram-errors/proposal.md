## Why

Код-ревью 2026-07-21 (Low, в бэклоге `docs/OPEN.md`): в проекте есть инвариант «`chat_id` в логах маскируется» — под него написан отдельный модуль `app/log_masking.py` (HMAC-SHA256 с доменом `logging:chat_id`, первые 8 hex), он задокументирован в README и соблюдается в хендлерах.

`app/handlers/errors.py:17` логирует `TelegramAPIError` через `%s`. Текст исключения формирует aiogram, и у части ошибок сырой `chat_id` **зашит прямо в сообщение**: `TelegramRetryAfter` («Flood control exceeded on method … in chat -100…»), `TelegramMigrateToChat`. Маскирование обходится не в обход правила, а мимо него — правило применяется к аргументам, а идентификатор приезжает внутри строки.

Сценарий не гипотетический: флуд-контроль на активной группе — то, ради чего этот класс ошибок вообще существует, а `TelegramRetryAfter` в проекте уже наблюдался. То есть инвариант тихо нарушается ровно там, где логи и смотрят — в разборе инцидента.

## What Changes

- Текст исключения Telegram перед записью в лог пропускается через санитайзер, заменяющий распознанные идентификаторы чатов на их маску.
- Санитайзер применяется в обработчике ошибок ко всем `TelegramAPIError`, а не точечно к двум известным классам: список ошибок с идентификатором в тексте задаётся aiogram и может пополниться в любой версии.
- Идентификаторы, для которых маска неприменима (маскирование не инициализировано), заменяются на нейтральную заглушку — сырое значение в лог не попадает ни при каком состоянии процесса.
- Диагностическая ценность записи сохраняется: тип ошибки, метод, задержка `retry_after` и всё остальное остаются на месте; исчезает только сам идентификатор.

## Impact

- **Код**: `app/handlers/errors.py` (единственная точка логирования этих исключений), `app/log_masking.py` (санитайзер текста рядом с существующей маской).
- **Зависимости**: новых нет; формат текста ошибок задаёт aiogram, поэтому распознавание строится на форме идентификатора, а не на разборе конкретной фразы.
- **Тесты**: `tests/test_log_masking.py` — тексты `TelegramRetryAfter` и `TelegramMigrateToChat`, отрицательные случаи (числа, которые не являются `chat_id`), поведение при неинициализированном маскировании.
- **Совместимость**: меняется только содержимое логов; поведение бота не затрагивается, выкатка не требует окна наблюдения.
