## Why

В реестре сто ручек; генерации касаются около сорока. Карта §2.1
классифицирует их по июльским свипам — другой копии, другому харнессу
(`eval_prod`) и одному режиму, — а с тех пор добавилось полтора десятка ручек и
две проваленные фазы оставили код за нейтральными дефолтами. M3R-150 (чистка)
стоит в P2 как «решение владельца по каждому пункту», но решать по памяти
нельзя: `reply_context_last_tokens` не читал никто, и нашли это свипом, а не
ревью. Решение владельца 2026-09-02: **перед чисткой — перепись**, по
измерению, а не по мнению.

## What Changes

- **Инструмент `tools/eval/knob_census.py`** (M3R-151): строит армы
  автоматически из `RUNTIME_FIELDS` — для каждой измеримой ручки два крайних
  значения диапазона (из подсказки домена реестра), для булевой — инверсия;
  для ручек, чей механизм выключен родительской ручкой, — те же экстремумы
  ещё и при включённом родителе. Прогон на прод-копии в двух режимах через
  `run_matrix` (парные дельты к C0), классификация по пре-регистрированному
  правилу, отчёт-таблица «ручка → класс по режимам → числа → предложение».
- **Правило классов пре-регистрируется** в `eval_thresholds.yaml`
  (`knob_census`) до прогона: *dead* — не читается на живом пути (статика);
  *gated* — экстремумы при выключенном родителе ничего не двигают, а при
  включённом двигают; *inert* — на всех экстремумах интервалы всех дельт
  внутри полосы допуска; *strong* — хотя бы одна значимая дельта не ниже
  планки силы; *weak* — остальное.
- Ручки конвейера ответа (темп, `/pivo`, причуды, троттлинг, настроение)
  **не измеряются**: харнесс их не исполняет; они попадают в таблицу с
  пометкой «вне оффлайн-замера».
- **Никаких удалений и слияний в этом change'е.** Его результат — таблица с
  цифрами и предложениями; решения по строкам и правки — M3R-150 отдельно.
- Дефолты не меняются; `generation_hash` не задет (правки только в
  `tools/eval`).
