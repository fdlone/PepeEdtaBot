## Context

`RUNTIME_FIELDS` — единственный источник ручек; у каждой есть домен с
подсказкой диапазона (`0..1`, `1..4`, `true/false`, `>= n`). `run_matrix`
принимает конфигурации как переопределения поверх дефолтов и даёт парные
дельты к C0. Ручки читаются в трёх местах: ядро генерации (`app/core`),
конвейер ответа (`reply_pipeline`), хендлеры. Харнесс исполняет только ядро.

## Decisions

### D1. Измеримы только ручки, которые читает ядро генерации

Множество определяется статикой: имя ручки встречается в модулях
`app/core/{response_generator,markov,candidate_scorer,slot_mutation,
interpolation,temporal,shadow_order,seed,collocations}.py`. Остальные —
«вне оффлайн-замера» с указанием, где читаются; их чистка решается по
достижимости, не по чувствительности.

### D2. Экстремумы диапазона, а не сетка

Перепись отвечает на вопрос «двигает ли ручка хоть что-то», а не «где
оптимум». Два арма на ручку — минимум и максимум домена (для `>= n` без
потолка — минимум и четырёхкратный дефолт, помечено); экстремум, равный
дефолту, пропускается; булева — инверсия. Составные (`length_mode_weights`)
и строковые (`markov_long_compression`) не свипуются, помечены.

### D3. Родительские ручки

Ручка, чей механизм выключен другой ручкой (пороги энтропии при
`markov_entropy_temp_gain = 0`, параметры сида при
`markov_seeded_candidate_ratio = 0`, пороги горячести при
`hot_ngram_slot_ratio = 0` и т. д.), измеряется дважды: при родителе на
дефолте (ожидаемо инертна) и при родителе, включённом значением из грида
его фазы. Класс *gated* ставится, когда первое инертно, а второе — нет.
Семейства перечислены в инструменте явно, как данные.

### D4. Классы — по пре-регистрированному правилу

Метрики классификации: `context_affinity_without_copy`,
`exact_context_copy_rate`, `repetition_rate`, `historical_meme_rate`,
`structural_window_escape`, `structural_pool_ecb`, `mean_response_length`.
Полоса допуска и планка силы — в `eval_thresholds.yaml`, до прогона.
Латентность печатается, но класс не определяет: прогон параллельный, и она
несравнима между армами.

### D5. C0 считается один раз на режим

Все армы парные к одному C0 (детерминизм: сид, промпты, копия). C0 снимается
отдельным заданием, армы — независимыми процессами; отчёт сшивает их по
позициям записей. Проверка: сводка C0 совпадает с базлайном версии набора.

### D6. Отчёт — числа, не текст

В таблицу попадают только классы, дельты и интервалы; текстов ответов и
n-грамм в ней нет. Предложение по строке (оставить / удалить / слить /
свести к константе) — рекомендация инструмента по классу, решение — M3R-150.

## Risks

- Экстремум может ломать форму (нулевой verbatim-штраф даёт пересказы) —
  это «сильная», а не «плохая» ручка; таблица показывает направление.
- Родитель, включённый значением грида, сам не оптимален; для *gated* класса
  это неважно — важен факт, что ребёнок вообще что-то двигает.
- Один прогон на ручку в двух экстремумах не видит немонотонность в середине
  диапазона; для чистки это допустимо — немонотонная ручка не инертна.
