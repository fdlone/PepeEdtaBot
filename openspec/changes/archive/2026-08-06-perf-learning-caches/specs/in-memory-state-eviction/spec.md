## ADDED Requirements

### Requirement: Производные кэши по чату ограничены наравне с прочим состоянием

Кэши, которые система строит по данным конкретного чата — выборки сообщений, индексы, словари, статистические профили, — SHALL подчиняться той же политике, что и остальное состояние в памяти: предел по сроку хранения и предел по числу чатов.

Основание то же самое: число чатов задаётся снаружи, а объём такого кэша растёт вместе с историей чата и ничем не ограничен сам по себе.

#### Scenario: Чат замолчал

- **WHEN** к производным кэшам чата не обращались дольше срока хранения
- **THEN** они удаляются из памяти

#### Scenario: Слишком много чатов

- **WHEN** число чатов с производными кэшами превышает предел
- **THEN** вытесняются кэши чатов с самым давним обращением

#### Scenario: Обращение после вытеснения

- **WHEN** в вытесненном чате снова требуется производный кэш
- **THEN** он строится заново из базы
- **AND** результат совпадает с тем, что был бы без вытеснения

### Requirement: Обновление кэша не превращается в полную пересборку на каждое сообщение

Если известен вклад нового сообщения в производный кэш, система SHALL обновлять кэш этим вкладом.

Полный сброс кэша на каждое выученное сообщение SHALL NOT применяться там, где инкрементальное обновление даёт тот же результат: кэш, который гарантированно холодный к моменту использования, не выполняет своей задачи.

Результат последовательности инкрементальных обновлений SHALL совпадать с результатом построения кэша с нуля.

#### Scenario: Сообщение выучено

- **WHEN** система выучила новое сообщение чата
- **THEN** производные кэши чата отражают его содержимое
- **AND** полная пересборка кэша не выполняется

#### Scenario: Эквивалентность инкрементального обновления

- **WHEN** кэш обновлён последовательностью сообщений инкрементально
- **THEN** его содержимое совпадает с построенным по тем же сообщениям с нуля
