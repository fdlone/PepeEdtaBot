## Why

Данные подписчиков `/pivo` (user_id, @ник, отображаемое имя) шифруются Fernet'ом, ключ для которого выводится как `base64(sha256(PIVO_ENCRYPTION_SECRET))` — без функции вывода ключа, без соли, без растяжения. Секрет проверяется только на длину не меньше 16 символов и на то, что это не плейсхолдер из `.env.example`, то есть парольная фраза вроде `pivopivopivopivo` считается допустимой. Для такого секрета SHA-256 не создаёт никакого барьера: перебор по украденной базе идёт со скоростью хеширования.

В этом же проекте уже есть правильный пример: ключ маскирования `chat_id` выводится через HKDF-SHA256 с доменной меткой `logging:chat_id`. То есть речь не о новой технике, а о том, чтобы применить принятую в проекте схему там, где защищаются персональные данные, а не идентификаторы в логах.

Второе, из того же места: при сборке упоминаний бот расшифровывает `encrypted_user_id` каждого подписчика и заново считает от него HMAC, чтобы сравнить с вызывающим, — хотя в строке уже лежит ровно этот HMAC (`user_hash`), просто не выбирается запросом. Сравнение при этом обычное, не константное по времени. Лишняя расшифровка на каждого подписчика — это ещё и работа на горячем пути `/pivo`.

## What Changes

- Ключ Fernet выводится через HKDF-SHA256 с доменной меткой (`pivo:fernet`), как уже сделано для маскирования `chat_id`.
- **Совместимость без простоя**: чтение идёт через набор ключей — сначала новый, затем прежний (`MultiFernet`). Существующие строки читаются старым ключом и перешифровываются новым при первой же записи профиля (`/pivo_on`, ежедневное обновление профиля). Отдельная миграция данных и остановка бота не требуются.
- Порог энтропии секретов поднимается: минимальная длина `PIVO_ENCRYPTION_SECRET` и `PIVO_HMAC_SECRET` — 32 символа. Существующий более короткий секрет останавливает старт с явной ошибкой, а не работает молча дальше.
- Сравнение идентификаторов подписчика с вызывающим переводится на хранимый `user_hash` и константное по времени сравнение; расшифровка `encrypted_user_id` для этого больше не выполняется.

## Impact

- **Код**: `app/domain/pivo.py` (вывод ключа, `MultiFernet`, сравнение хешей), `app/config/settings.py` (порог длины секретов), `app/repositories/chat_members_repo.py` (выбирать `user_hash`), `app/services/pivo_service.py` (передача хеша вызывающего).
- **BREAKING для эксплуатации**: деплой с секретом короче 32 символов не стартует. Это осознанный выбор: молчаливый старт со слабым ключом — ровно та ситуация, которую изменение и закрывает. Требуется запись в `docs/OPERATIONS.md` и в `.env.example`.
- **Данные**: миграция схемы не нужна. Перешифровка ленивая; строки чатов, где никто больше не пишет, остаются читаемыми старым ключом столько, сколько он присутствует в наборе.
- **Совместимость**: `PIVO_HMAC_SECRET` не меняется — от него зависят и `chat_hash`/`user_hash` в базе, и маска `chat_id` в логах; смена схемы HMAC потребовала бы полной пересборки таблиц и в этом изменении не делается.
- **Тесты**: значение, зашифрованное прежней схемой, читается после перехода; запись перешифровывает его новым ключом; секрет короче порога останавливает старт; сравнение вызывающего с подписчиком работает без расшифровки user_id.
