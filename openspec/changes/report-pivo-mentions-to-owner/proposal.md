## Why

Изменение по O2 (PR #105) добавило то, чего у задачи не было полгода, — машинный сигнал: после каждого `/pivo` в лог пишется агрегат `pivo mentions:` с числом подписчиков, распределением по путям упоминания и количеством entity `text_mention` / `mention` в разборе сервера. Именно по нему решается главный вопрос: приняты ли упоминания по `user_id` вообще.

**Сигнал есть, но владелец не может его прочитать.** Доступа к логам у владельца нет и не предвидится — ни в момент вызова, ни потом. То есть проверка «после первого живого `/pivo` посмотри строку в логе» невыполнима, а вместе с ней невыполним и весь протокол наблюдения: пункт «если `text_mention=0` — не наблюдать, а разбирать» никто не сможет применить.

Это дефект проектирования наблюдаемости, а не пожелание: канал доставки сигнала выбран так, что получатель до него не дотягивается. У бота при этом уже есть прямой канал к нужному человеку — `OWNER_ID`.

## What Changes

- После успешно отправленного `/pivo` бот отправляет владельцу в личку короткий отчёт с тем же агрегатом, что идёт в лог: сколько подписчиков, сколько упомянуто по `user_id`, сколько строкой `@ник`, сколько пропущено, сколько entity `text_mention` и `mention` вернул сервер.
- В отчёт добавляется **название чата** — маскированный `chat_id` из лога человеку ничего не говорит, а владельцу нужно понимать, о каком чате речь. Название в лог не пишется, только в личное сообщение владельцу.
- Отчёт управляется ручкой `pivo_report_to_owner` (дефолт `true`): выключается через `/set`, без рестарта.
- **Отказ доставки не ломает `/pivo`**: если владелец не начинал диалог с ботом, заблокировал его или `OWNER_ID` не задан, сообщение просто не уходит — вызов `/pivo` уже состоялся, и ронять его из-за отчёта нельзя.
- Логирование агрегата остаётся как есть: личка — дополнительный канал, а не замена.

## Impact

- **Код**: `app/handlers/pivo.py` (отправка отчёта после успешного `reply`), `app/config/registry.py` + `runtime_state.py` + `settings.py` (ручка), `.env.example`.
- **Внешние вызовы**: один `send_message` в личку владельца на успешный `/pivo`. Объём ограничен суточной квотой `/pivo` (3 вызова на участника, 5 для админа), так что поток сообщений не может стать шумом сам по себе.
- **Приватность**: в отчёте нет ников, имён и идентификаторов подписчиков — только числа и название чата. Получатель — владелец бота, который и так состоит в этом чате.
- **Тесты**: `tests/test_handlers.py` — отчёт уходит владельцу, содержит числа из агрегата и не содержит персональных данных; при выключенной ручке не уходит; при отсутствии `OWNER_ID` не уходит; **сбой отправки не ломает `/pivo`** и не откатывает квоту.
- **Документация**: README (описание отчёта и ручки), `docs/OPEN.md` — строка O2 описывает протокол наблюдения через личку, а не через лог.
