## Why

Код-ревью 2026-07-21 (Low, в бэклоге `docs/OPEN.md`): `COMMAND_COOLDOWNS_SECONDS` в `main.py:26` содержит **одну** запись — `clear`. Мидлварь троттлинга при этом полностью готова: ключ `(chat_id, user_id, command)`, TTL и `max_keys` у состояния, отдельный кулдаун на сами уведомления об отказе. Не хватает не механизма, а списка.

Без лимита остаются `/config`, `/help`, `/ping`, `/stats`, `/pivo_on`, `/pivo_off`, `/pivo_privacy`. Из них:

- `/config` не имеет ни `AdminOrOwner`, ни `GroupOnly` — вызвать может кто угодно и в личке;
- `/pivo_on` и `/pivo_off` пишут в SQLite на **каждый** вызов;
- `/stats` читает агрегаты из базы.

Любой участник может гонять `/config` в цикле и заставлять бота отвечать бесконечно: усиление трафика от имени бота и риск флуд-бана — то есть тот самый `TelegramRetryAfter`, из-за которого в проекте есть отдельная задача про маскирование `chat_id` в тексте ошибки.

Решение из раздела «осознанно отложено» про «`/config` без `AdminOrOwner`» этот аспект **не покрывает**: оно про раскрытие данных (секретов в `RuntimeState` действительно нет), а не про то, что команду можно вызывать без ограничений.

## What Changes

- Кулдауны получают все пользовательские команды, а не одна. Значения назначаются по классу команды (дешёвое чтение / чтение из базы / запись в базу), а не подбираются поштучно — обоснование в `design.md`.
- Поведение при отказе остаётся прежним по умолчанию — тихий пропуск; явный ответ («подожди столько-то») сохраняется только там, где молчание читается как поломка, как сейчас у `/clear`.
- Кулдаун применяется в личных чатах так же, как в группах: `/config` доступна в личке, и именно там её никто не видит.
- Ограничение считается на пару «пользователь + чат», как уже устроен ключ мидлвари: один шумный участник не молчит бота для остальных.
- Права доступа команд **не меняются**: `/config` остаётся доступной всем, как решено ранее. Это изменение про частоту, а не про доступ.

## Impact

- **Код**: `main.py` (таблица кулдаунов и набор команд с уведомлением); `app/middlewares/throttling.py` — только если понадобится различать классы команд, сама механика уже есть.
- **Поведение**: участник, вызывающий команду чаще лимита, перестаёт получать ответ до истечения кулдауна. Для `/pivo_on` и `/pivo_off` это заметно: повторное нажатие «включить» в пределах окна останется без ответа — поэтому им, вероятно, нужен явный ответ при отказе, см. `design.md`.
- **Тесты**: `tests/test_middlewares.py` — по представителю каждого класса команд; проверка, что лимит считается на пару «пользователь + чат»; проверка, что `/pivo` продолжает подчиняться собственной дневной квоте независимо от кулдауна.
- **Документация**: README — раздел про команды, упомянуть наличие лимитов; `docs/OPEN.md` → `docs/CLOSED.md`.
