## Context

Мотивация — `proposal.md`, требования — `specs/command-rate-limits/spec.md`.

Мидлварь троттлинга уже делает всё, что нужно: ключ `(chat_id, user_id, command)`, TTL и `max_keys` у состояния, `notify_on_throttle` для команд с явным ответом, отдельный кулдаун на сами уведомления (`notify_cooldown_sec`, аудит N6). Регистрируется она в `configure_dispatcher` до роутеров, то есть отсекает вызов раньше хендлера — побочные эффекты не наступают.

Поэтому решение — не про механизм, а про числа и про то, кому из команд нужен явный ответ при отказе.

## Goals / Non-Goals

**Goals:**

- Закрыть усиление трафика (бесконечный `/config`) и запись в базу по каждому нажатию (`/pivo_on`/`/pivo_off`).
- Назначить значения по классам, чтобы список было легко пополнять при появлении новой команды.

**Non-Goals:**

- Не меняем права доступа команд. Решение «`/config` без `AdminOrOwner`» принято осознанно и здесь не пересматривается.
- Не выносим кулдауны в ручки `RuntimeState`: это не тюнинг генерации, а защитный предел; его место — в коде рядом с регистрацией мидлвари, а не в том, что правится командой `/set`.
- Не трогаем `/pivo` — у него собственная суточная квота и анти-повтор; кулдаун ему назначается только как страховка от частоты, не как замена квоты.

## Decisions

### D1. Три класса вместо поштучного подбора

| Класс | Команды | Окно | Почему столько |
|---|---|---|---|
| Дешёвое чтение, ответ из памяти | `/ping`, `/help`, `/config`, `/pivo_privacy` | 15 с | Достаточно, чтобы человек прочитал ответ и повторил осмысленно; цикл вызовов гасится сразу. Меньше — не мешает атаке, больше — раздражает при обычном использовании. |
| Чтение из базы | `/stats` | 60 с | Агрегаты в чате не меняются за секунды; минута не мешает нормальному интересу и снимает нагрузку с базы. |
| Запись в базу | `/pivo_on`, `/pivo_off` | 30 с | Подписка — редкое действие; человек нажимает её осознанно один раз. Окно достаточное, чтобы «включить/выключить» подряд не крутило запись, и достаточно короткое, чтобы передумавший человек не ждал. |
| Уже назначено | `/clear` | 1 ч | Не трогаем. |
| Права владельца | `/set`, `/setprob` | не ограничиваем | Доступны только `OWNER_ID` (фикс O5); ограничивать владельца от самого себя смысла нет, а тюнинг ручек по своей природе итеративный. Это то самое «зафиксированное исключение с причиной» из спеки. |

### D2. Явный ответ при отказе — только `/pivo_on` и `/pivo_off`

Эти две команды человек нажимает намеренно и ждёт подтверждения («готово, буду звать»). Тишина в ответ на «включи меня» читается как «бот сломался» — тот же довод, по которому `notify_on_throttle` уже включён для `/clear`.

Остальные остаются молчаливыми: `/config` в цикле — это ровно тот случай, где ответ на отказ и есть усиление трафика, которое мы гасим. Частота самих уведомлений ограничена `notify_cooldown_sec` и так.

### D3. Значения живут в `main.py` рядом с регистрацией мидлвари

Таблица уже там; расширяем её и `notify_on_throttle`, ничего не переносим. Комментарий над таблицей объясняет классы из D1 — чтобы следующая команда получила окно по принадлежности к классу, а не по вкусу.

## Risks / Trade-offs

- **Окно мешает нормальному использованию** (двое подряд спросили `/stats`) → окно считается на пару «участник + чат», второго человека не задевает; для одного и того же человека минута между запросами статистики не является ограничением на практике.
- **Тихий отказ выглядит как поломка** → на командах, где это существенно (`/pivo_on`/`/pivo_off`), включено уведомление; остальные либо мгновенно повторяемы, либо это ровно тот сценарий, который мы гасим.
- **Список снова отстанет от кода** (появится команда без окна) → классы в комментарии и тест, проверяющий, что у каждой зарегистрированной команды есть окно либо явно зафиксированное исключение.
