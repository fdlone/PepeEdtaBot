# Глубокий аудит системы генерации ответов

Дата: 2026-07-02. Аудит выполнен по коду в `main` (adf9aa9). Только анализ — код не менялся.
План работ по итогам аудита: [DIALOGUE_GENERATION_ACTION_PLAN.md](DIALOGUE_GENERATION_ACTION_PLAN.md).

> **Статус:** документ — снапшот на момент аудита. Часть описанного поведения
> уже изменена по плану (см. таблицу Progress в плане): отбор кандидата теперь
> softmax, а не argmax (QW1); fallback-фразы — пулы с анти-повтором, а не две
> строки (QW2); задержка набора зависит от длины (QW3); casefold-матчер включён
> по умолчанию (QW4); финальная пунктуация варьируется (QW5); анти-повтор
> распространён с коротких на все ответы — окно 20, точные совпадения
> отбрасываются, триграммные пересечения штрафуются (S1).

**TL;DR:** это не «бот со списком фраз», а зрелый движок: пер-чатовая цепь Маркова
3-го порядка на SQLite с бэкоффом до 2/1, температурным исследованием, контекстным
смещением, анти-повторными штрафами, генерацией 5 кандидатов и выбором лучшего по
скорингу. Инженерное качество высокое (9/10), но *дизайн диалога* — консервативный:
система усердно борется с плохими ответами и почти ничего не делает для того, чтобы
ответы были *живыми*. Нет настроения, нет памяти о собеседниках, нет редких событий,
нет пер-пользовательских реакций, а fallback-фразы — две захардкоженные строки.
Самый большой рычаг — не в Маркове, а в слое «личности» поверх него.

```

              │     └─ lexicon (BAD_ENDING_WORDS)
```

Мёртвого кода в ядре практически нет; единственная «спящая» ветка —
mid-generation jump (`jump_probability = 0.0`, `app/core/markov.py:1511`,
сознательно выключено с комментарием).

## Phase 2 — Трассировка пайплайна

Для каждого входящего текстового сообщения (`app/handlers/learning.py:111`):

1. **Вход:** `router.message(F.text)`; отсекаются не-группы, боты, команды.
2. **Препроцессинг:** `strip_leading_bot_vocative` («Пепе, …» → «…»), затем
   `sanitize_text`: удаление ссылок → редактирование PII → удаление @упоминаний →
   схлопывание повторов символов (`ааааа`→`аа`) → нормализация пробелов.
3. **Фильтр обучаемости:** ≤500 символов и ≥2 токена.
4. **«Intent detection»:** его нет как такового — единственный intent — «упомянули
   бота» (`bot_is_mentioned`: @username, алиасы `pepe`/`пепе`, reply на сообщение бота).
5. **Решение отвечать:** `should_reply_to_message` — упомянут → всегда; иначе
   cooldown 45 с **и** бросок кубика с p = 0.08.
6. **Контекст:** до 12 последних токенов из (reply-to текст + текущее сообщение).
7. **Генерация (`ResponseGenerator.generate`):** до 10 попыток (первые 5 — с
   контекстом, потом без), эскалация randomness от 2.0 к 3.0 по попыткам;
   каждая попытка:
   - выбор старта: seed (не используется в проде) → «скрытый контекстный старт»
     (вероятность (2.2−1)/2.2 ≈ 55%: находится 3/2-грамма контекста среди состояний
     модели, старт *не включается* в вывод) → глобальный взвешенный старт;
   - блуждание по цепи до 90 шагов / 45 токенов / 280 символов с бэкоффом 3→2→1,
     контекст-биасом с распадом `0.92^step`, штрафами за повторы
     токенов/биграмм/триграмм;
   - финализация: обрезка репетитивного хвоста → до границы предложения → чистка
     концовки (BAD_ENDING_WORDS, висящая пунктуация, добавление «.») → снятие
     ведущей пунктуации;
   - quality-гейты отклонения: слишком коротко (<5 симв.), низкое разнообразие,
     копия контекста, «context-heavy» (≥92% overlap).
8. **Фильтры кандидата:** не равен текущему сообщению; короткий ответ не из
   последних 5 коротких; не дословная копия обучающего сообщения (кэш 500 последних).
9. **Отбор:** максимум по `CandidateScore.total`
   (completion + diversity + length + relevance − repetition).
10. **Постобработка:** опциональная капитализация предложений (по умолчанию выкл.).
11. **Отправка:** `reply_humanized` — chat action «печатает» + случайная пауза
    350–1100 мс → `message.reply`.
12. **Обучение (finally):** сообщение всегда записывается в модель после ответа.

Fallback-ветки: «Пока мало материала, поболтайте ещё 🙂» (мало данных) и
«Собираю мысли... Напишите ещё пару сообщений 🙂» (генерация не удалась) —
**единственные захардкоженные реплики, всегда одинаковые**.

## Phase 3 — Используемые техники

| Техника | Где | Комментарий |
|---|---|---|
| Цепь Маркова 3-го порядка с бэкоффом 3→2→1 | `app/core/markov.py` | пер-чатовая модель в SQLite, LRU-кэши в памяти |
| Взвешенный сэмплинг с частотной степенью | `weighted_next_choice` | `count^power`, power падает с ростом randomness |
| Температурное исследование (exploration) | `sampled_exploration` + `exploration_weighted_choice` | треугольное сэмплирование температуры; в exploring-режиме выбор через `expovariate` — Gumbel-подобный трюк |
| Контекстный биас с распадом | `context_decay = max(0.25, 0.92^step)` | токены/пары/триплеты контекста получают ×1.8–2.2 в начале |
| «Скрытый контекстный старт» | `_select_contextual_state` | старт от n-граммы контекста, не эхом в вывод — умное решение против попугайства |
| Fuzzy-матчинг (casefold + префикс, кириллица ≥6 общих букв) | `app/core/context_state_matcher.py` | по умолчанию **выключен** |
| Анти-повторные штрафы | `weighted_next_choice` | recent-window 10 токенов, seen pairs/triplets (bounded 80) |
| Quality-гейты + best-of-N скоринг | `_finalize_attempt`, `app/core/candidate_scorer.py` | reject-ветки + 5-компонентный скор |
| Анти-повтор коротких ответов | `recent_short_replies` (deque 5) | только для ответов ≤3 токенов |
| Verbatim-фильтр | `LearningService.is_verbatim_copy` | защита от цитирования корпуса |
| Вероятностный триггер + cooldown | `app/core/reply_policy.py` | p=0.08, 45 с |
| Шаблонная комбинаторика | `/pivo` | top × body × bottom × intro, слоты `{mentions_inline}`, `{time_phrase}`, `{target_bullet}` |
| Имитация набора текста | `reply_humanized` | typing action + случайная задержка |

Чего **нет**: state machine настроения, reaction tables, синонимика, эмодзи-логика,
память о пользователях, редкие события, временнáя/сезонная логика.

## Phase 4 — Оценка вариативности

**Марков-ветка.** Теоретическое число уникальных ответов растёт экспоненциально с
корпусом: при живом чате в ~1000 сообщений — сотни тысяч различимых траекторий;
дословные повторы длинных ответов практически исключены (verbatim-фильтр +
стохастика + randomness 2.0 — очень «горячий» сэмплинг: `next_explore ≈ 0.48`,
`next_power ≈ 0.40`). Собственный baseline проекта (`tools/generation_baseline.json`,
синтетический корпус из 24 сообщений): distinct-1 = 0.10, distinct-2 = 0.16, средняя
длина 7.7 токена, повторных биграмм между ответами 0 — на малом корпусе межответное
разнообразие низкое, что ожидаемо.

**Предсказуемость по осям:**

- *Лексика* — непредсказуема (хорошо).
- *Форма* — очень предсказуема: почти всегда 5–14 «контентных» токенов
  (`natural_length` штрафует всё вне этого окна), почти всегда заканчивается точкой
  (`finalize_reply_ending` дописывает «.»), одно-два предложения, без эмодзи, без
  вопросов как намеренного жеста.
- *Поведение* — полностью предсказуемо: упомянули → ответит всегда и сразу; не
  упомянули → 8% после кулдауна. Ноль сюрпризов на уровне «когда и как бот вступает».

**/pivo-ветка.** Комбинаторика без цели: 22 top × 16 body × 18 bottom ≈ **6 336
скелетов** (×16 intro в части body → до ~25k текстов); с целью: 20×16×18 ≈ 5 760 ×
14 intro. Вероятность точного повтора при еженедельном созыве мала, но **top-фразы
узнаваемы после 5–10 использований** — воспринимаемое разнообразие исчерпывается
куда раньше комбинаторного.

**Фиксированные реплики:** 2 fallback-строки — 100% повтор при каждом срабатывании.

## Phase 5 — Анализ слабостей

1. **Best-of-5 скоринг систематически сжимает дисперсию.** Скорер всегда выбирает
   максимум → «средние безопасные» ответы выигрывают, хвостовые (странные, смешные) —
   стабильно проигрывают. Это главный парадокс системы: randomness 2.0 генерирует
   хаос, а скорер его вычищает. Перцептивно бот становится «ровным», а ровность
   читается как механичность.
2. **Захардкоженные fallback'и (2 строки).** Именно fallback пользователи видят в
   самые «голодные» моменты — и он всегда идентичен. Мгновенно выдаёт бота.
3. **Анти-повтор только для коротких ответов.** Средние ответы (4–8 токенов) на
   бедном корпусе могут повторяться между сессиями — памяти о недавних *полных*
   ответах нет.
4. **Форма ответа монотонна.** Всегда утвердительное предложение с точкой. Никогда:
   вопрос как приём, многоточие, ВЕРХНИЙ РЕГИСТР, одно слово, стикер-подобная
   реакция. Живые люди варьируют форму сильнее, чем лексику.
5. **Ноль долговременного состояния.** Бот не знает, кому отвечает, что говорил
   вчера, какая тема «горячая». Каждый ответ — из вакуума. Это самый большой разрыв
   с ощущением «живости».
6. **Поведенческий триггер — константа.** p=0.08 не зависит от активности чата,
   времени суток, «зацепило/не зацепило». Нет всплесков и затиший — а именно
   неравномерность читается как характер.
7. **`/pivo` top-фразы приедаются**: пул выбирается равномерно, без weighted-decay
   недавно использованных.
8. **`normalize_lower=false` по умолчанию** фрагментирует модель («Пиво»≠«пиво» —
   разные состояния), а fuzzy casefold-матчинг, который это компенсирует, тоже
   выключен по умолчанию.
9. **Спящий jump-механизм** (`jump_probability=0.0`) — готовый механизм «смены темы
   посреди фразы» лежит выключенным.
10. **Эмодзи стираются на этапе токенизации** (`TOKEN_RE = \w+|пунктуация`) — модель
    никогда не выучит и не воспроизведёт эмодзи чата, хотя это половина
    эмоционального сигнала Telegram-чата.

## Phase 6 — Взгляд геймдизайнера диалогов

- **RimWorld / Dwarf Fortress:** повествование рождается из *состояния*, а не из
  текста. У персонажей есть mood, отношения, память о событиях. У бота нет ни одной
  скрытой переменной состояния — это разрыв №1.
- **Left 4 Dead (AI Director):** интенсивность управляется дирижёром —
  накопление/разрядка. Аналог для бота: динамическая p(ответа) — молчать в затишье,
  включаться в перепалку, изредка «прорываться» серией. Сейчас — плоская константа.
- **GTA / STALKER (реплики прохожих):** маленькие пулы фраз работают, потому что
  жёстко привязаны к *контексту события* и имеют cooldown per-line. Урок для
  `/pivo`: не расширять пулы бесконечно, а не повторять недавнее и привязывать выбор
  к параметрам (время, день недели, кто зовёт).
- **The Sims:** «симлиш» доказывает, что смысл не обязателен — интонация и тайминг
  важнее. Марков-бред уже смешной; система его слишком старательно фильтрует.
- **Fallout / Firewatch:** редкие «личные» реплики (узнал игрока, сослался на
  прошлое) дают непропорционально сильный эффект. Одна фраза бота «опять ты про
  пиво, как в прошлый вторник» стоит сотни обычных ответов.

**Ключевой принцип, которого не хватает:** perceived intelligence =
память + уместность + редкость, а не качество каждого отдельного предложения.

### Ответ на главный вопрос

**«Что дало бы наибольший эффект без LLM?»** — три вещи, в порядке убывания
impact/effort:

1. **Вернуть хаос, который система сама у себя отбирает** (день работы суммарно):
   softmax вместо argmax при выборе кандидата, вариатор формы/пунктуации, пул
   fallback'ов, эмодзи-канал. Движок уже генерирует разнообразие — его душат на
   последней миле.
2. **Дать боту скрытое состояние** (2–3 дня): mood чата + AI-Director вероятности
   ответа. Урок RimWorld/L4D: характер — это не текст, это *когда и как* система
   себя ведёт. Неравномерность вступления в разговор сделает для «живости» больше,
   чем любые улучшения текста.
3. **Дать боту память** (неделя): running jokes на всплесках n-грамм и лёгкие
   пер-пользовательские квирки. Одна реплика «бот помнит» в неделю создаёт репутацию
   «он живой» — это самый дорогой, но и самый мощный пункт.

Архитектура готова ко всему списку: registry для новых параметров,
trace-инфраструктура для отладки, eval-харнесс для измерения distinct-n до/после —
каждое изменение можно вести через существующий baseline-процесс.
