# Промпт: реализация Markov 2.0R Phase 9 (M2R-900..902)

Ты работаешь в репозитории PepeEdtaBot — Telegram-бот на цепях Маркова
(Python 3.12+, aiogram v3, SQLite, unittest, ruff, mypy strict для `app/`).
Прочти перед началом: `docs/ARCHITECTURE.md`, `docs/GENERATION_PIPELINE.md`,
спецификацию `docs/M2R_PHASE8_INTERPOLATION.md` (этот документ — источник
требований), устройство гейтов в `tools/eval/` и `eval_thresholds.yaml`,
вердикты Phase 2/3 в `docs/` — они задают стиль и стандарт доказательств.

## Задача

Реализовать мягкую интерполяцию распределения шага генерации:
`P = (1−β)·P3 + β·P2proj`, где P2proj — распределение order-2 по проекции
(w2,w3) текущего order-3-состояния. Управляется новым runtime-ключом
`MARKOV_INTERP_ORDER2_WEIGHT` (β, float, [0,1], default 0.0). Фича уходит в
деплой выключенной.

## Жёсткие инварианты (нарушение любого = задача не выполнена)

1. **β = 0 → побайтная идентичность текущему поведению.** Ранний return до
   любого чтения order-2-слоя и любых слияний. Доказательство —
   `tools/generation_hash.py`: хэш при β=0 равен хэшу до твоих правок. Добавь
   этот регресс в тесты фазы.
2. **Детерминизм порядка кандидатов.** Сэмплинг зависит от порядка списка
   (инвариант кэшей Phase 1). Слитый список упорядочен детерминированно:
   первичный ключ — убывание веса, вторичный — лексикографический по токену.
   Одинаковый вход → побайтно одинаковый слитый список.
3. **Слияние на нормализованных распределениях**, не на сырых счётчиках:
   объёмы слоёв несопоставимы. Нормализация каждого слоя в собственном пуле,
   затем взвешенная сумма.
4. **Кэши Phase 1.** Обе политики (`markov_cache_incremental` true/false)
   дают побайтно одинаковый вывод при любом β. Если кэшируешь слитые
   распределения — β входит в ключ кэша и `/set` нового β инвалидирует;
   проще и предпочтительнее — кэшировать слои раздельно (как сейчас) и
   сливать при чтении.
5. **Бэкофф-путь не меняется**: шаг, где order-3-состояние отсутствует, идёт
   в order-2 ровно как сейчас. Order-1 не возвращается. Фильтры, скоринг,
   best-of-N, verbatim/echo-гейты — без изменений.
6. **Privacy-инварианты проекта**: никакого сырого `chat_id` в новых
   лог-сообщениях (маскирование как везде); в тестах/фикстурах только
   синтетические ID из списка `tests/test_no_real_chat_ids.py`; телеметрия —
   только числа.
7. **Реестр настроек**: новый ключ — строка в `RUNTIME_FIELDS`
   (`app/config/registry.py`) + поля в `Settings` и `RuntimeState`; валидация
   диапазона [0,1]; доступность через `/set` с действием до рестарта — как у
   остальных ключей.

## Объём работ

### M2R-900 — интерполированный шаг (`app/core/markov.py`)
Найди место, где для существующего order-3-состояния строится распределение
следующего токена, и внедри слияние по формуле выше за флагом β>0. Чтение
order-2-проекции — через существующий порт `markov_port.py` (если нужного
метода чтения нет — добавь в порт и в `MarkovRepo`, сохранив правило «порт
объявляет ровно то, что вызывается»; проверка — `tests/test_layering.py`).

### M2R-901 — телеметрия (`app/core/generation_telemetry.py`)
Два счётчика по образцу телеметрии бленда Phase 3: (a) доля шагов, где
order-2-слой добавил хотя бы одного нового кандидата к пулу P3; (b) средняя
total-variation дистанция слитого распределения от чистого P3. Вывод — в тот
же канал, что существующие метрики телеметрии (виден eval-отчёту).

### M2R-902 — тесты
- unit: корректность слияния (веса, нормализация, β=0/β=1 граничные),
  детерминизм порядка, поведение при пустой/отсутствующей P2proj (слияние
  вырождается в чистую P3 — не в ошибку);
- property: для случайных пулов при β=0 слитое распределение == P3 побайтно;
- интеграционный: обе политики кэша при β=0.3 дают одинаковый
  `generation_hash`; смена β через `/set` отражается в следующем ответе;
- регресс: `generation_hash` при β=0 == эталону до правок.

### Eval-обвязка
- `tools/eval/matrix_phase9_grid.yaml`: руки β ∈ {0.15, 0.30, 0.50} + C0.
  Идентификатор конфигурации: проверь реестр конфигов в `tools/eval/` (C5
  может быть занят/зарезервирован) и возьми следующий свободный, единообразно
  с существующей схемой имён.
- `eval_thresholds.yaml`: гейт `phase9_interp` дословно по §7 спецификации,
  с датой регистрации. Пороги после этого не трогаются.
- Если рендер гейтов в `tools/eval/report.py` не умеет какое-то из условий
  (напр. «нижняя граница CI дельты > −0.02») — добавь и покрой в
  `tests/test_eval_protocol.py`, как сделано для гейтов Phase 6/7.
- Перенеси перепись состояний из спецификации в `tools/eval/state_census.py`
  (census + симуляция интерполяции), чтобы мотивационные цифры были
  воспроизводимы одной командой на любой копии БД.

- Не добавлять зависимости.
