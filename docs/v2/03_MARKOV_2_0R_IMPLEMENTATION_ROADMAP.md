# PepeEdtaBot Markov 2.0R — Revised Implementation Roadmap

**Status:** Proposed, v1.1 (после внешнего ревью)
**Scope:** усечённый и дополненный относительно исходного Markov 2.0
**Constraint:** генерация чисто марковская; без LLM/embeddings/внешних AI API

---

## 0. Изменения v1.1 относительно v1.0

По результатам внешнего ревью:

1. Short-слой переведён с `count × D(last_seen)` на **экспоненциально
   затухающие счётчики** (устранено искажение «100 старых + 1 вчерашнее
   употребление»). ТЗ §7.
2. Long-слой получает **сублинейное сжатие весов** при нормализации;
   добавлен обязательный эксперимент калибровки blend (M2R-215). ТЗ §8.
3. Коллокации переведены со склейки токенов на **уровень скоринга**
   (ADR-016): rebuild модели невозможен ⇒ несовместимые токенизации
   неустранимы. M2R-320 переписан.
4. Реверсная цепь понижена из «ядра» в **основной эксперимент Phase 5**
   (ADR-012 Provisional) с числовыми критериями промоушена; индекс
   ограничен order-2.
5. Seed выбирается **композитным seed_score** (idf × support ×
   branching-полоса), не max-IDF; IDF-документ определён как
   нормализованное сообщение с инкрементальным df-агрегатом.
6. Гейт anti-cycle стал **двумерным**: rate × harm.
7. GC разделён на дефолтный (`count == 1`) и расширенный opt-in режим
   (малый count × возраст × нет рекуррентности × нет ассоциации);
   формулировка «count > 1 не удаляется никогда» смягчена до
   «не удаляется по умолчанию».
8. Реакции-бандит: reward отложенный и агрегированный по окну,
   минимум trials до эксплуатации.
9. Добавлен обязательный **ablation-принцип** (P8 Vision) и отдельный
   документ `05_MARKOV_2_0R_EVAL_PROTOCOL.md`; метрики seeded разделены
   по знаменателям; введён `context_affinity_without_copy`.
10. Терминология: seeded-генерация документируется как **statistical
    lexical anchoring**, не topic detection.

Каждая фаза самоценна: после любой можно остановиться в консистентном
состоянии.

## Phase 0 — Baseline и eval-инфраструктура

### M2R-000 — Заморозка baseline Markov 1.x

Фиксированный seed-датасет + анонимизированный слепок реальной модели;
метрики baseline по протоколу дока 05.

### M2R-001 — Оффлайн eval-раннер с ablation-матрицей

`python -m tools.eval --db <snapshot> --config <matrix.yaml> --seed N`

Прогоняет конфигурационную матрицу (V1; V2+entropy; V2+blend; V2+memes;
V2+seeded; полный V2), печатает метрики и дельты против baseline
с доверительными интервалами (bootstrap). Формат отчёта, набор промптов,
объёмы выборок, протокол ручной оценки — нормативно в доке 05.

**Принцип:** «2.0R лучше V1» — недостаточный результат; обязательна
атрибуция вклада по фичам. Раннер — гейт каждой последующей фазы
и smoke в CI.

**Acceptance:** baseline и ablation-прогон воспроизводимы с точностью
до seed.

## Phase 1 — Инструментация, shadow-селектор, кэш

### M2R-010 — Диагностика распределений

Branching, энтропия, confidence — в trace-агрегаты; поведение не меняется.

### M2R-020 — Shadow order selector

Считает гипотетический выбор order-4 без изменения генерации.
Данные — гейт Phase 7.

### M2R-030 — Bounded-кэш распределений

LRU/TTL+LRU с лимитом; инвалидация при обучении. Кэшируются сырые
`(count, s_value, s_updated_at)` или blended-распределения с коротким
TTL — `s_eff` времязависим, «замороженное» кэширование запрещено (ТЗ §14).
Ранняя фаза: слои + реверс + best-of-N умножают lookup'ы; бюджет p95
без кэша невыполним.

## Phase 3 — Temporal layer

### M2R-200 — Схема слоёв

Миграция: `count/first_seen/last_seen` (long) + `s_value/s_updated_at`
(short) на переход. Обучение обновляет оба слоя атомарно.

### M2R-210 — Затухающие счётчики + blend

Реализация ТЗ §7–8: счётчики short, сублинейное сжатие long
(`MARKOV_LONG_COMPRESSION`), α-blend по mood, нормализация по
объединению. Long-слой не затухает (ADR-011); смена half-life обнуляет
short-слой с предупреждением.

### M2R-215 — Калибровка blend *(новое, обязательный эксперимент)*

Сетка (α-профиль × форма/β сжатия) на eval-раннере. Двойная целевая
функция: скорость отражения свежего временнóго среза И прохождение
мем-регресс-кейса. Результат — обновлённые дефолты + записка с сеткой
в docs/.

### M2R-220 — GC-джоб (двухуровневый, opt-in)

Дефолтный режим (`count == 1`, возраст ≥ 365) и расширенный
(`count ≤ 3` × возраст ≥ 3 лет × нет рекуррентности × не входит в
активные мемы/коллокации) — оба выключены по умолчанию, оба с
обязательным dry-run. ТЗ §15.

**Acceptance фазы:** свежий лексикон отражается быстрее (временнóй срез);
мем-регресс проходит; property-тесты счётчиков (порядок наблюдений не
влияет; вклад возрастом hl = 0.5) зелёные.

## Phase 4 — PMI-мемы + коллокации (scoring-level)

### M2R-300 — PMI/lift/LLR-анализатор

Без изменений: пороги support/recency обязательны, meme_score
интегрируется в hot n-grams (единый механизм персональности).

### M2R-310 — Интеграция с hot n-grams

Замена чисто частотного отбора там, где выигрывает на eval.

### M2R-320 — Коллокационный скоринг *(переписано, ADR-016)*

Активные коллокации дают бонус кандидату за целостное воспроизведение
и штраф за разрыв (только если правый токен был статистически доступен).
Каноническая токенизация не меняется; retirement коллокации безопасен.
Реестр per-chat со статусами, лимитом, `/stats`-видимостью,
`/clear confirm`. Склейка в токенизации — future proposal с
`tokenization_version`.

**Acceptance:** топ-20 мемов chat-specific (ручная проверка по протоколу
дока 05); ablation «V2+memes» показывает вклад; переклееных/разорванных
артефактов в выборке нет.

## Phase 5 — Statistical lexical anchoring *(основной эксперимент)*

Статус: ADR-012 Provisional. Фаза спроектирована как эксперимент
с явными критериями промоушена и полным путём отката.

### M2R-400 — Реверсный индекс order-2 + df-агрегат

Таблица `markov_reverse` (только order-2), `markov_token_df`, `N_docs`;
атомарное обучение; бэкфилл-миграция из прямой таблицы с отчётом
о фактическом storage-приросте.

### M2R-410 — Seed score и двунаправленная генерация

Композитный `seed_score = normalized_idf × support_factor ×
branching_quality` (полоса, не порог — ТЗ §9.4); генерация хвоста
прямой цепью и головы реверсной; seeded-кандидаты в общий best-of-N
без приоритета; прозрачный fallback при отсутствии пригодного seed.

### M2R-420 — IDF-компонент скоринга кандидатов

ТЗ §9.7; вес 0 ⇒ поведение 1.x.

### M2R-430 — Решение о промоушене *(новое)*

По данным ≥ согласованного объёма прогонов и телеметрии:
`seeded_present_rate`, `seeded_win_rate_given_present`,
дельта `context_affinity_without_copy` против ablation без seeded,
latency p95, storage. Исходы: ADR-012 → Accepted, либо фича выключается,
реверсные структуры замораживаются, решение фиксируется с цифрами.
Плохой trade-off (например, редкие победы при существенном росте
латентности/объёма) — валидное основание отказа.

## Phase 6 — Anti-cycle и jumps *(gated: rate × harm)*

**Гейт двумерный:** телеметрия должна показать И частоту циклов
(`cycle_detection_rate`), И их вред (`cycle_harm_rate`: отклонения
кандидатов по цикл-коррелирующим причинам + ручная оценка выборки —
протокол в доке 05). Обоснование: цикл ≠ вред; «да да да» — легитимный
ответ Pepe. Непревышение любого порога ⇒ фаза закрывается без
реализации с фиксацией цифр.

## Phase 8 — Мета-тюнинг по реакциям *(эксперимент)*

### M2R-800 — Отложенный агрегированный reward

Реакции на сообщение аккумулируются окно
`MARKOV_PRESET_REWARD_WINDOW_HOURS` (дефолт 24) и зачисляются пресету
одним агрегатом; событий per-user нет. Мгновенная реакция рекламой
качества пресета не считается.

### M2R-810 — Бандит над пресетами

Равномерная ротация до `MARKOV_PRESET_MIN_TRIALS`, затем
epsilon-greedy/Thompson. Влияет только на выбор пресета (ADR-014).
Закрытие: неразличимость пресетов за срок ⇒ выключение с фиксацией.

## Вычеркнутые фичи (ADR-013, ADR-016)

| Фича | Причина |
|---|---|
| Hierarchical scopes | Один чат ⇒ global ≡ chat; user scope противоречит `003_anonymize_authors` и разрежен. Возврат — только отдельный opt-in proposal. |
| Conditional state | Категориальные размерности режут малый корпус до перманентного backoff'а — сложный no-op. |
| Beam search | Best-of-N + scorer уже покрывают поиск; beam смещает к усреднённым ответам; максимальная стоимость при недоказанной пользе. |
| Склейка коллокаций в токены | Rebuild невозможен ⇒ несовместимые токенизации сосуществуют вечно. Заменено скоринг-уровнем (ADR-016). |

## Правила реализации

Каждая фаза: миграция → ядро → unit → интеграционные → eval по протоколу
дока 05 (включая ablation-конфигурацию фазы) → trace → флаг → документация.
Фаза не завершена без не-регрессии на eval. Фазы 5–7 имеют явные гейты;
«закрыто без реализации с цифрами» — полноценный результат.

---

## Success criteria

Против замороженного baseline, по протоколу дока 05:

- exact-copy rate ↓; патологические повторы ↓;
- distinct-2/3 ↑ без деградации связности (ручная оценка);
- `context_affinity_without_copy` ↑ (эффект Phase 5, если промоутнута);
- свежий лексикон отражается быстрее; мем-регресс-кейс проходит;
- вклад каждой включённой фичи атрибутирован ablation'ом;
- GC в дефолте не трогает `count > 1`; расширенный GC — только явный
  opt-in с dry-run;
- p95 в бюджете; privacy не изменена; каждая подсистема отключаема.
