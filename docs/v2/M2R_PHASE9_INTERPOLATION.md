# Phase 9 — интерполяция order-3 × order-2 (M2R-900)

**Статус:** предложено. Гейт `phase9_interp` регистрируется в
`eval_thresholds.yaml` **до** запуска грида (правило пре-регистрации, doc 05 §4).
**Мотивация измерена** на `db_prod_copy` (снимок июля 2026, боевой чат
-1001147461458 → в артефактах репозитория заменить на синтетический ID по
`tests/test_no_real_chat_ids.py`), скрипт переписи — приложить в
`tools/eval/state_census.py` при реализации.

---

## 1. Проблема, которую решает фаза

Вердикты Phase 2, 3 и 7 упёрлись в одну стену с трёх сторон: цепь order-3 на
этом корпусе почти детерминирована. Перепись прод-копии по боевому чату:

| факт | значение |
|---|---|
| состояний order-3 | 26 385 |
| с ровно одним продолжением | **97.9%** (94.6% по посещениям) |
| в средней зоне H_norm [0.2, 0.8), где sampling-ручки имеют рычаг | **2 состояния (~0.0%)** |
| order-2 для сравнения: посещений с реальным выбором (H_norm ≥ 0.8) | ~30% |

Следствия уже задокументированы: энтропийная температура инертна (Phase 2),
темпоральный бленд инертен (Phase 3), order-4 не выбирается никогда (Phase 7),
exact_copy 22% — структурный, а не пайплайновый.

Дополнительно **закрыт измерением** запасной путь из Phase 3-вердикта:
сублинейная компрессия счётчиков (pow 0.75 / pow 0.5 / log) переводит в среднюю
зону **ноль** пулов — она сплющивает и без того почти равномерные ветвящиеся
пулы к равномерным, а детерминированным не помогает ничем. Экстраполяцию
«0.3% → ~9%» из Phase 3 считать опровергнутой в части механизма: среднюю зону
на фикстуре создавало несогласие двух слоёв, а не компрессия. Ре-замер Phase 2
«после компрессии» из роадмапа исключить.

## 2. Идея

Заменить жёсткий бэкофф «order-3 нашёл → order-2 не смотрим» мягкой
интерполяцией на каждом шаге, где state order-3 существует:

```
P(w | s3=(w1,w2,w3)) = (1−β)·P3(w | w1,w2,w3) + β·P2(w | w2,w3)
```

где `β = markov_interp_order2_weight ∈ [0,1]` — вес order-2-проекции.
`β = 0` — фича выключена (ранний return до любых слияний, побайтная
идентичность 1.x — инвариант проверяется `tools/generation_hash.py`).
Шаги, где order-3 промахнулся, идут прежним бэкоффом в order-2 без изменений.
Order-1 не возвращается.

**Измеренный эффект** (симуляция на прод-копии, боевой чат, β = 0.3):

| зона | до | после |
|---|---|---|
| детерминированные шаги | 97.9% | **72.7%** |
| средняя зона H_norm [0.2, 0.8) | ~0.0% | **26.1% состояний / 26.7% посещений** |
| почти-равномерная [0.8, 1.0] | 2.1% | 1.2% |

У 25.6% детерминированных order-3-состояний проекция (w2,w3) предлагает 2–10+
альтернатив (у 1673 — десять и более). Остаточные 72.7% — разреженность до дна
(order-2 там тоже хранит один вариант); их лечит только рост корпуса.

При β = 0.5 в почти-равномерную зону уходит 10% шагов — граница агрессивности;
грид не должен выходить за 0.5.

## 3. Почему это не «выбор ценой салата» by design

Механизм инжекции нижнего порядка — ровно тот, за который была удалена цепь
order-1 (миграция 013). Отличие текущей системы от того решения: между цепью и
выводом стоит best-of-N (фильтры verbatim/echo/анти-повтор + softmax-отбор по
скорингу). Интерполяция расширяет **пул кандидатов**, а отбор остаётся прежним:
несвязный кандидат проигрывает скоринг, связный — впервые получает шанс
существовать. Гипотеза фазы: разнообразие пула вырастет (distinct-2/3 ↑, copy ↓)
без падения топикальности (affinity_without_copy — пол гейта) и без роста
повторов. Если гипотеза неверна — гейт обязан это поймать, для того он и
двумерный по качеству.

## 4. Задачи

- **M2R-900 — интерполированный шаг.** Точка входа — построение распределения
  шага в `app/core/markov.py`. Слияние на нормализованных распределениях
  (не на сырых счётчиках — объёмы слоёв несопоставимы). Порядок кандидатов в
  слитом списке детерминирован (сортировка по токену при равенстве весов) —
  от порядка зависит сэмплинг, это уже инвариант кэшей Phase 1.
- **M2R-901 — телеметрия вклада.** В `generation_telemetry`: доля шагов, где
  order-2-слой добавил ≥1 нового кандидата; средняя TV-дистанция слитого
  распределения от чистого P3 (зеркально телеметрии бленда Phase 3). Только
  числа, без текста и немаскированных идентификаторов.
- **M2R-902 — кэш-инварианты.** Слитые распределения не кэшируются как
  отдельная сущность либо кэшируются с ключом, включающим β; инкрементальные
  дельты Phase 1 обязаны инвалидировать/обновлять обе составляющие. Обе
  политики кэша (incremental / full-reset) дают побайтно одинаковый вывод при
  любом β.

Вне фазы (follow-ups, каждый за своим гейтом): M2R-910 — ре-замер энтропийной
температуры Phase 2 **поверх** победившей β (единственная конфигурация, в
которой у неё впервые есть градуированный сигнал; новый гейт, `phase2_entropy`
спент); M2R-920 — β, зависящая от объёма модели чата (`chat_model_volume` уже
читается на каждое сообщение); M2R-930 — continuation counts в духе Kneser-Ney
для P2 на реверсном индексе миграции 020 (данные M2R-400 уже копятся).

## 7. Гейт `phase9_interp` (пре-регистрация до грида)

Рука проходит, если **все** условия выполнены (CI 95%, значимость — интервал
исключает 0, doc 05 §4):

1. `distinct-2` **и** `distinct-3` выросли значимо vs C0 — целевая метрика:
   впервые в проекте у неё есть механизм расти;
2. `exact_context_copy_rate` не вырос значимо (ожидается снижение — не
   требуется);
3. `context_affinity_without_copy`: нижняя граница CI дельты > −0.02 (пол —
   тот же класс защиты, что зарезал M2R-110);
4. `repetition_rate` не вырос значимо; `cycle_detection_rate` < 0.05
   (страховка: интерполяция меняет топологию блужданий, вердикт Phase 6 снят
   на другой топологии);
5. `performance.generation_p95` ≤ 150 мс;
6. **ручной раунд связности** (см. §8) — доля «связных» ответов руки не ниже
   C0 более чем на 10 п.п.

Ни одна рука не прошла → фича остаётся `β = 0`, вердикт-документ по образцу
Phase 2/3, пороги не трогаются.

## 8. Ручной раунд — с починенным протоколом

Урок Phase 4: agreement 0.17 делает вердикт резиновым. Требования к раунду
Phase 9 (фиксируются до раунда):

- бинарная рубрика «связно / салат» с письменным определением и 10
  калибровочными примерами, размеченными до основного раунда;
- ≥3 рейтера, слепая подача (рука не видна), перемешанные C0/руки + декои;
- порог валидности: Fleiss' kappa ≥ 0.4; ниже — раунд не засчитывается,
  рубрика дорабатывается, раунд повторяется (не «усредняем и верим»);
- объём: 30 ответов на руку минимум.

## 9. Риски

| риск | контроль |
|---|---|
| словесный салат в проде на живых промптах | ships-disabled; ручной раунд в гейте; `/set` откат без рестарта; β — плавная ручка |
| латентность (слияние двух распределений на каждом шаге) | бюджет p95 в гейте; слияние — O(k) по кандидатам, k мал; замерить cache_hit_rate до/после |
| рассинхрон с кэшами Phase 1 | M2R-902 + сверка `generation_hash` обеих политик кэша при β>0 в тестах |
| β=0 не байт-идентичен | ранний return до слияния; регресс `tools/generation_hash.py` в CI-набор фазы |
| малые чаты: у β другой эффект при ином объёме слоёв | вне фазы (M2R-920); в грид не тащить |

## 10. Встраивание в роадмап 2.0R

Фаза добавляется в `03_MARKOV_2_0R_IMPLEMENTATION_ROADMAP.md` после Phase 8
(мета-тюнинг по реакциям). Пересечений с Phase 8 нет: бандит выбирает пресет
(ADR-014) и распределение шага не трогает; β может войти в состав пресетов
отдельным решением после промоушена обеих фич. Диапазон задач 5xx остаётся
свободным (у Phase 5 задачи в 4xx), Phase 9 берёт 9xx.

Строка в таблицу приоритетов:

| Фаза | Ценность | Риск | Приоритет | Гейт |
|---|---|---|---|---|
| 9. Интерполяция 3×2 | Высокая (снимает стену Phase 2/3/7, измерено) | Средний (связность) | P1 | `phase9_interp` |

**Порядок относительно Phase 5 (lexical anchoring).** Обе фичи меняют состав
пула кандидатов: anchoring — на уровне сидов, интерполяция — на уровне шага.
Гейты обеих сняты против чистого C0 и про совместный эффект не говорят
ничего. По ablation-принципу роадмапа (v1.1 п.9): если обе проходят свои
гейты, перед совместным включением в прод обязателен комбинированный
ablation-прогон (anchoring + β победившей руки) с проверкой, что
`affinity_without_copy` и p95 не деградируют против лучшей одиночной
конфигурации. Бюджет латентности — главное место столкновения: C4 уже стоит
p95 ≈ 119 мс, запас до 150 мс мал.

Success criteria роадмапа фаза адресует напрямую: «distinct-2/3 ↑ без
деградации связности (ручная оценка)» — это дословно условия 1 и 6 гейта.

## 11. Определение готовности фазы

Код за флагом в main, тесты зелёные (unit на слияние/нормализацию/порядок,
property на инвариант β=0, интеграционный на кэш-политики), грид прогнан,
вердикт-документ написан, `eval_thresholds.yaml` содержит гейт с датой
регистрации раньше даты грида.
