# PepeEdtaBot Markov 2.0R — Vision & Feature Proposal

**Status:** Proposed, v1.1 (после внешнего ревью)
**Target:** PepeEdtaBot
**Constraint:** генерация остаётся полностью марковской/статистической; без LLM, embeddings, нейросетевого reranker'а, семантических моделей, RAG и внешних AI API.

## 1. Назначение

Markov 2.0R улучшает качество, разнообразие, тематичность и адаптивность
PepeEdtaBot, не отказываясь от ключевой идеи проекта: бот генерирует текст
из статистических моделей переходов, выученных на сообщениях чата.

Текущий проект уже имеет per-chat цепь order-3 с backoff на order-2,
context-aware старты, best-of-N генерацию, скоринг кандидатов, mood,
hot n-grams и механизмы flavor/personality.

Отличие 2.0R от исходного 2.0: план откалиброван под **фактический деплой —
один локальный чат с долгоживущими мемами**. Ядро смещается к
**entropy-aware, время-адаптивной и лексически заякоренной** марковской
системе; фичи, чья стоимость оправдана только масштабом, исключены.

## 2. Non-goals

Вне рамок Markov 2.0R:

- LLM-генерация или LLM-скоринг кандидатов;
- transformer/sentence-transformer embeddings;
- нейросетевые классификаторы сантимента/интента;
- RAG / векторные базы; внешние семантические API;
- отдельная нейросеть, обученная на чате;
- хранение сырых сообщений сверх существующей retention-политики;
- **семантическое определение темы** — seeded-генерация есть
  statistical lexical anchoring (см. §4, M2R-06), а не topic detection;
- **изменение канонической токенизации** — коллокации работают на уровне
  скоринга (ADR-016);
- **hierarchical scopes** (ADR-006 Rejected);
- **conditional Markov state** (ADR-007 Superseded);
- **beam search** (ADR-009 Rejected).

## 3. Ключевые принципы

### P1 — Марковская чистота

Каждый сгенерированный токен выбирается из статистического распределения
переходов; состояние содержит всю информацию для определения распределения
следующего шага.

### P2 — Направление цепи — часть модели

Реверсные переходы — такая же марковская статистика, как прямые.
Двунаправленная генерация от seed-токена не нарушает P1.

### P3 — Свежесть без забвения

Long-term слой не затухает по умолчанию: долгоживущие мемы — ценность
целевого чата. Свежесть достигается blend'ом со short-слоем и сублинейной
нормализацией long-весов, а не удалением старого (ADR-011).

### P4 — Неопределённость управляет случайностью

Состояния с высокой уверенностью дают стабильные продолжения; состояния
с высокой энтропией допускают исследование.

### P5 — Объяснимость

Для каждого кандидата система способна объяснить: порядок, вероятность,
энтропию, branching, слой, seed-токен (если был), штрафы и бонусы.

### P6 — Сохранение приватности

Без хранения сырых сообщений сверх существующей политики, без
пер-пользовательских моделей (совместимо с `003_anonymize_authors`).
Долговременное знание — только агрегаты. Следствие: **rebuild модели
из сырья невозможен**, поэтому любые изменения представления данных
обязаны быть forward-compatible (это причина ADR-016).

### P7 — Эмпирика вместо интуиции

Каждая фича принимается или отклоняется по метрикам eval-протокола
(`05_MARKOV_2_0R_EVAL_PROTOCOL.md`) против замороженного baseline.
«Закрыть фазу без реализации» — валидный результат.

### P8 — Изолируемость эффектов (ablation)

Каждая существенная фича должна допускать оценку в изоляции: eval-раннер
прогоняет конфигурационную матрицу (V1; V2+entropy; V2+blend; …) и
атрибутирует вклад каждой фичи отдельно. «2.0R лучше V1» без разбивки
по фичам — недостаточный результат.

## 4. Состав фич

### M2R-01 — Entropy-aware sampling

`H(S)`, нормализация по branching; нормализованная энтропия модулирует
температуру выборки и (опционально) число кандидатов best-of-N.

### M2R-02 — Метрики уверенности как first-class сигналы

`branching_factor`, `max_probability`, `normalized_entropy`, `confidence` —
вычисляются всегда, пишутся в телеметрию, используются генерацией.

### M2R-03 — Двухслойная временнáя модель

- **long-term**: без decay; при нормализации веса сжимаются сублинейно
  (`log(1+count)` или `count^β`), чтобы исторические гиганты не подавляли
  blend полностью;
- **short-term**: экспоненциально затухающие счётчики
  (`value = value·2^(−Δt/hl) + 1` при наблюдении) — математический
  эквивалент суммы decay по всем наблюдениям при O(1) хранении;
- blend `P = α·P_short + (1−α)·P_long`; α зависит от mood; калибровка
  α и β — обязательный эксперимент (M2R-215).

Физическое удаление — только отдельным opt-in GC-джобом; дефолтный
критерий — `count == 1` и возраст ≥ года.

### M2R-04 — Статистическое обнаружение локальных мемов

PMI, lift, LLR поверх hot n-grams с порогами support и recency:
находить характерное для чата, а не просто частое.

### M2R-05 — Коллокации на уровне скоринга

Обнаруженные устойчивые пары дают бонус кандидатам, воспроизводящим
коллокацию целиком, и штраф за её разрыв. **Каноническая токенизация
не меняется** (ADR-016): склейка токенов исключена из scope, т.к.
несовместимые токенизации при невозможности rebuild (P6) неустранимы.

### M2R-06 — Statistical lexical anchoring (seeded-генерация)

Реверсная цепь (order-2) + двунаправленная генерация от seed-токена,
выбранного композитным `seed_score = normalized_idf × support_factor ×
branching_quality`. Это лексическое якорение, не определение темы:
редкий-в-чате токен входящего сообщения с пригодной статистикой в модели.
Статус фичи — основной эксперимент Phase 5 с числовыми критериями
промоушена (ADR-012 Provisional).

### M2R-07 — Тематический IDF-скоринг

Компонент скоринга: IDF-взвешенное пересечение кандидата с последними
сообщениями. Документ для IDF = нормализованное сообщение; df ведётся
инкрементальным агрегатом (privacy-совместимо).

### M2R-08 — Anti-cycle и динамический jump *(gated)*

Реализуется только если телеметрия покажет и частоту циклов, и их
фактический вред (двумерный гейт: rate × harm).

### M2R-09 — Variable-order с order-4 *(gated)*

Только если shadow-статистика покажет реальный выбор order-4 в значимой
доле генераций без роста exact-copy.

### M2R-10 — Мета-тюнинг по реакциям *(экспериментально)*

Бандит над пресетами; reward — отложенный и агрегированный по окну,
не мгновенная реакция. Влияет только на выбор пресета (ADR-014).

### M2R-11 — Телеметрия генерации

Порядок, энтропия, branching, слой, α, seed, причины отклонений, циклы,
hit-rate кэша. Сырой текст — только opt-in локально.

## 5. Порядок реализации

1. Baseline + eval-раннер с ablation-матрицей (протокол — док 05).
2. Телеметрия, shadow order selector, bounded-кэш.
3. Entropy-aware sampling.
4. Двухслойная модель + калибровка blend (M2R-215).
5. PMI-мемы + коллокации (scoring-level).
6. Lexical anchoring: реверс order-2 + seeded + IDF-скоринг (эксперимент).
7. Anti-cycle (гейт rate × harm).
8. Order-4 (гейт shadow).
9. Реакции-бандит (эксперимент).

Детали — в `03_MARKOV_2_0R_IMPLEMENTATION_ROADMAP.md`.

## 6. Критерии успеха

Против замороженного baseline по протоколу дока 05:

- context_affinity_without_copy растёт; релевантность не деградирует;
- exact-copy rate снижается;
- патологические повторы снижаются;
- distinct-2/3 растут без превращения ответов в шум;
- текущий словарь чата отражается быстрее;
- долгоживущие мемы сохраняются и воспроизводимы (мем-регресс-кейс);
- вклад каждой фичи атрибутирован через ablation;
- генерация объяснима; LLM не введены; privacy не изменена;
- p95 латентности в бюджете.
