## С чего начинать следующую сессию

1. **Решение по коду Phase 2** (за владельцем) — фаза 3 его подготовила
   цифрами. Гипотеза «Phase 3 разгладит пиковые пулы» проверена напрямую:
   blend переводит **43% пулов, у которых есть выбор**, в полосу, где
   температурная ручка имеет рычаг (0 → 23 из 53). Но на фикстуре такие пулы —
   1.0% всех шагов, поэтому адресуемая масса выросла с ~0% до 0.4%.
   Экстраполяция на полный корпус (там 20.9% многовариантных шагов против 1.0%
   в фикстуре) дала бы ~9% против измеренных в фазе 2 0.3% — **это арифметика
   на допущении, а не замер**. Рекомендация: оставить код фазы 2, перезамерить
   после окна накопления с **новым** гейтом; удалить — тоже защитимо на тех же
   числах. Разбор: `docs/eval_reports/eval_2026-08-12_phase3-verdict.md`.
2. Окно накопления: цепь начинает копить собственные метки с первого сообщения
   после рестарта с миграцией 018. Через 2-4 недели — `/opsx:propose
   markov2r-phase3-calibration` (M2R-215): перезамер blend на живом корпусе.
   **В тот же PR отдельным коммитом положить `openspec archive
   markov2r-phase3-temporal-layer-core`** — та же конвенция, что и для фазы 2.
3. Фоновая гигиена (вне 2.0R, по желанию): подъём yanked `aiogram 3.29.0`
   отдельным change; `actions/checkout@v4` предупреждает о Node 20.
