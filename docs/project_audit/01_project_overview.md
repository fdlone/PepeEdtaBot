## What this project is

**PepeEdtaBot** is a Telegram group-chat bot that learns from the chat's own
messages and replies with text generated by a **per-chat Markov chain** — no
external LLM is involved (`README.md:3`, `app/core/markov.py`). It also ships a
self-contained joke feature, `/pivo`, that pings opted-in members to gather in
Discord.

Two responsibilities dominate the codebase:

1. **Markov learning + generation** — every group text message trains
   per-chat n-gram transition tables (orders 1/2/3) and may trigger a
   best-of-N generated reply. Entry point: `app/handlers/learning.py:110`
   (`on_text_message`). Engine: `app/core/markov.py`.
2. **`/pivo` opt-in mention system** — privacy-preserving subscriber list with
   HMAC-indexed, Fernet-encrypted member records and per-day call quotas.
   Entry point: `app/handlers/pivo.py`; crypto in `app/domain/pivo.py`.

Everything else (admin/config commands, stats, throttling, privacy redaction,
log masking) is supporting infrastructure.

## Architecture in one paragraph

A single async process. `main.py` is the **composition root**: it loads
`Settings`, opens the SQLite `Database` facade, builds the singletons
(`MarkovGenerator`, `PivoService`, `LearningService`, `RuntimeState`), registers
one throttling middleware and five routers on an aiogram `Dispatcher`, and runs
long-polling. Dependencies are injected into handlers through aiogram's
`dp[...]` workflow-data map. The code is layered: `handlers → services →
repositories → infrastructure(Database)`, with `core` (pure generation/text
logic) and `domain` (pivo crypto/templates) as mostly-pure helper layers, and
`config`/`presentation` as cross-cutting support. Full detail in
[03_architecture.md](03_architecture.md).

## Notable characteristics

- **Privacy is a first-class design goal.** Raw message text column was dropped
  (migration `005`); only `normalized_text` (links/mentions/PII stripped) is
  kept. `author_id` is forced to `0` (migration `003`). `/pivo` stores only
  salted HMAC hashes + Fernet ciphertext. `chat_id` is masked in logs. See
  `README.md:140-151` and verify in [08_security.md] (M3).
- **Heavy investment in generation quality.** `app/core/markov.py` (1438 lines)
  plus `candidate_scorer.py`, `context_state_matcher.py`, and a best-of-N
  selection loop in `response_generator.py` implement reply-context biasing,
  repetition penalties, fuzzy (casefold/prefix) context matching, and many
  reject heuristics. Several knobs are off by default
  (`fuzzy_context_*`, `auto_capitalize_replies`).
- **Config registry pattern.** Runtime-mutable settings are declared once in
  `app/config/registry.py` and flow automatically into `Settings`,
  `RuntimeState`, and the `/set` command — a deliberate anti-duplication design.
- **Large, structured test suite.** ~24 test modules, several >1000 lines
  (`tests/test_handlers.py` 1014, `tests/test_markov_and_text.py` 1166). Quality
  assessed in [12_testing.md] (M5).
